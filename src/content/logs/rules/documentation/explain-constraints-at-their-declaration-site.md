---

**규칙:** 아키텍처 설명은 정확히 한 계층에만 두고, **기계가 검사하는** 제약의 근거는 그것을 바꾸려면 반드시 열게 되는 파일에, **검사되지 않는** 것의 근거는 최상위 문서에 둔다. 최상위 문서는 어느 쪽이든 **전체 지도**를 갖는다.

## 왜

세 층이 각각 다른 일을 한다.

- **중복 금지** — 같은 근거가 두 계층에 살면 한쪽만 고쳐지고, 그 순간 어느 쪽이 아키텍처인지 알 수 없어진다. ADR 실무에서 관찰된 실패 모드가 정확히 이것이다: 결정이 문서 갱신을 앞지르고, **한 번 갱신을 잊는 순간 그 문서는 낡은 것으로 취급되어 다시는 갱신되지 않는다.**
- **근거를 아래로 내리는 이유는 갱신 확률이다.** Fluri 등의 comment-code 공진화 연구에서 **주석 변경의 97%가 대응하는 소스 변경과 같은 리비전에서** 일어난다. 고치는 파일 안에 있으면 같이 고쳐진다.
- **그런데 근접성은 부패를 막지 못한다.** code-comment inconsistency는 독립 연구 분야이고 버그 유입과의 상관까지 보고된다. **주석은 코드에 붙어 있는 문서일 뿐, 실행되지도 테스트되지도 않는다.** 그래서 근거를 아래로 내리는 선택은 **낡아도 검사가 위반을 잡아 주는 제약에서만** 안전하다. 검사가 없으면 낡은 주석은 낡은 문서와 똑같이 사람을 잘못 이끈다.
- **지도를 없애면 안 된다.** 최상위를 포인터 한 줄로 비우면 어떤 제약이 존재하는지 알 수 없어 열어 볼 파일을 고를 수 없다. 지도가 없으면 아래층은 발견되지 않는다.
- **그렇다고 최상위에 다 넣어서도 안 된다.** `agent instruction bloat`는 Thoughtworks Technology Radar에 오른 이름 있는 실패 모드이고, 그 근거는 *Lost in the Middle*(Liu et al., TACL 2023) — 관련 정보가 컨텍스트 **중간**에 있을 때 성능이 가장 낮고 컨텍스트가 길어질수록 더 떨어진다.

## 예시

**최상위 층 — 지도**(`AGENTS.md` / `PROJECT.md`): 존재하는 제약의 목록과 **각각이 어디서 선언되는지**, 용어집, 탐색 가이드, 그리고 기계가 검사하지 않는 규약의 근거까지. 검사되는 제약의 *근거*는 여기 쓰지 않는다.

**변경 지점 층 — 그 제약을 바꾸려면 열게 되는 파일**:

```ts
// apps/api/vitest.config.mts  ← 이 레포에 실제로 이렇게 쓰여 있다
// Vitest의 기본 변환기(esbuild)는 emitDecoratorMetadata를 emit하지 않아
// Nest의 DI가 design:paramtypes를 읽지 못한다. SWC로 교체해 메타데이터를 살린다.
swc.vite({ /* ... */ })
```

```jsonc
// turbo.json — 이 규칙을 적용했을 때의 모습.
// 현재 레포의 turbo.json에는 주석이 없고, 이 근거는 milestones/01-package-boundaries.md에 있다.
// (주석 파싱 자체는 turbo 2.10.9에서 //·/* */ 모두 실측 확인)
"boundaries": {
  "tags": {
    // domain은 바깥을 모른다 — app·shared를 알기 시작하면
    // 도메인 규칙이 전송·화면 사정에 따라 바뀐다.
    "domain": { "dependencies": { "deny": ["app", "shared"] } }
  }
}
```

**변경 지점이 여럿일 때** — `turbo boundaries`에서 "domain은 바깥을 모른다"는 제약은 패키지별 `turbo.json`의 `tags`, 루트 `turbo.json`의 `deny` 규칙, `package.json`의 `exports`에 걸쳐 선언된다. 이때 근거는 **선언된 모든 곳이 아니라 그 제약을 바꾸려면 반드시 여는 한 곳**(= 규칙 행렬이 있는 루트 `turbo.json`)에 둔다. 나머지 선언 지점에는 아무것도 쓰지 않는다 — 쓰면 패키지 수만큼 복제된다.

**구조가 이미 표준이다** — AGENTS.md 스펙의 중첩 규약이 같은 모양이다. 에이전트는 편집 중인 파일에서 트리를 거슬러 올라가며 가장 가까운 파일을 읽고, 가까운 것이 이긴다. OpenAI 메인 레포에는 AGENTS.md가 88개 있다.

## 비예시

- **지도를 포인터로 비움** — 최상위에 "의존 규칙의 원본은 `turbo.json`이다" 한 줄만. 열어 볼 파일을 고를 근거가 없다.
- **양쪽에 같은 서술** — 최상위 문서에 "domain은 app·shared를 의존하지 않는다 — 도메인은 바깥을 모른다"를 쓰고 설정 주석에도 같은 근거를 쓴다. 규칙이 늘어날 때 한쪽만 고쳐지고, 그 순간 어느 쪽이 아키텍처인지 알 수 없어진다. (단, **고도가 다르면 같은 서술이 아니다** — 전역 원칙과 특정 값의 사유는 다른 층이다. 이 경계는 아직 판정 기준이 없는 약한 자리다.)
- **사용 지점에 흩뿌림** — `packages/core/src/health.ts` 위에 "이 패키지는 app을 의존하면 안 된다" 주석. 규칙이 바뀌면 전부 찾아 고쳐야 한다.
- **검사 없는 제약의 근거를 아래로 내림** — 아무도 실행하지 않는 스크립트의 규약을 그 스크립트 주석에만 둔다. 안전망이 없으므로 발견되지 않고, 낡아도 아무 일이 일어나지 않는다. 이런 건 위에 둔다.

## 적용 범위·예외

**성립 조건이 먼저다: 근거를 아래로 내리는 것은 위반이 실행 실패로 잡히는 제약에서만 안전하다.** 검사가 없으면 근거는 최상위로 올린다.

- **에이전트가 주 독자일 때 갈린다.** 최상위 문서는 매 세션 전량 로드되지만 설정 주석은 그 파일을 열 때만 만난다. 근거를 내리면 **예방이 사후 교정으로 바뀐다** — 검사가 그 교정을 맡을 때만 성립하는 거래다.
- **기각된 대안과 시점이 있는 결정**(왜 A 대신 B를 골랐나, 언제 뒤집혔나)은 현재 제약을 설명하지 않으므로 변경 지점에 두면 다음 편집자가 지우고 싶어진다. **ADR 류의 이력 문서**로 보낸다 — 이 규칙이 다루는 범위 밖이다.
- **학습 자료와 실행 기록은 대상이 아니다.** 읽어서 배우는 것이 목적인 문서(교재·프로젝트 스펙)에서 근거를 걷어내면 문서의 목적 자체가 사라진다. 승인·판정을 거쳐 결과가 로그에 박힌 마일스톤 스펙은 시점이 박힌 기록이라 고치면 기록이 아니게 된다 — ADR 예외와 같은 계열이다. 실제 사례: `learn/turborepo-platform-lab`의 `PROJECT.md`·`milestones/*`는 이 규칙을 만든 레포이면서도 **의도적으로 적용 대상에서 뺐다.** 규칙을 만든 곳이라고 규칙을 적용할 대상인 것은 아니다.
- **도구로 강제되지 않는 규약**(커밋 시점, 리뷰 절차, 진행 방식)은 최상위 문서가 본문까지 갖는다.
- **엄격 JSON**(`package.json` 등)은 주석을 받지 못한다 → `"//"` 키 관행을 쓰거나 인접 파일로 옮기고, 옮겼다는 사실을 지도에 적는다.
- **생성이라는 제3의 답이 있다.** 지도를 변경 지점의 태그된 주석에서 **추출·생성**하면 두 계층을 다 갖고도 원본은 하나다. 중복이 "반드시" 갈라지는 것은 손으로 양쪽을 쓸 때뿐이다. 계층이 늘어 손유지가 버거워지면 이쪽을 먼저 검토한다.
- **설명이 문단을 넘어가면** 설정이 아니라 설계 문서다 → 빼내고 링크만 남긴다.

## 확인 방법

1. **(기계)** 지도의 각 제약 항목이 `파일:키` 형태 앵커를 갖고, 그 파일이 실제로 존재하는지 검사한다. 앵커 없는 항목은 지도가 아니라 서술이다.
2. 최상위 문서에서 제약 하나를 고른다 → **어느 파일을 열어야 바꿀 수 있는지** 문서만 읽고 짚을 수 있어야 한다. 못 짚으면 지도가 부족하다.
3. 그 파일을 연다 → **왜 이 값인지**가 있어야 한다. 없으면 근거가 변경 지점에서 떨어진 것이다.
4. 두 곳의 문장이 겹치면 — **그 제약에 실행 가능한 검사가 있으면 아래만, 없으면 위만** 남긴다. (겹침 발견 시 무조건 아래를 남기면 검사 없는 규약이 발견 불가능해진다.)
5. 주석을 지웠다고 가정한다 → 다음 사람이 설정을 잘못 고칠 것 같으면 맞는 자리에 있는 것이고, 그냥 배경 설명이면 문서로 보낸다.
