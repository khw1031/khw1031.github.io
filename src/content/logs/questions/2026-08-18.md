### 작업큐가 왜 필요한거지?

작업 큐는 **사용자 요청을 오래 걸리는 작업에서 분리해, 요청은 빨리 끝내고 작업은 안전하게 나중에 처리하기 위해** 필요합니다.

예를 들어 사용자가 AI 분석을 요청하면 모델 호출은 수십 초 걸리거나 일시적으로 실패할 수 있습니다. HTTP 요청 안에서 바로 실행하면 서버 워커가 그 시간 내내 묶이고, 서버가 재시작되면 진행 중인 일을 잃을 수 있습니다. 큐에 `분석할 작업`을 먼저 저장하면 요청에는 접수 결과만 돌려주고, 별도 워커가 꺼내 처리할 수 있습니다.

큐는 다음 문제도 맡습니다.

- 여러 워커가 같은 작업을 동시에 처리하지 않도록 **점유**한다.
- 워커가 죽으면 임대 시간이 지난 작업을 다시 꺼내 **복구·재시도**한다.
- 요청이 갑자기 몰리면 작업을 대기열에 쌓아 처리 속도에 맞춰 **완충**한다.
- 실패한 작업에 재시도 간격과 최대 횟수를 적용하고, 계속 실패하면 별도 보관한다.

다만 큐가 모든 일을 마법처럼 한 번만 처리해 주지는 않습니다. 외부 API 호출 직후 워커가 죽으면 같은 작업이 다시 실행될 수 있으므로, 결제·이메일·AI 결과 저장처럼 부작용이 있는 작업은 작업 ID를 멱등성 키로 써서 중복 실행에도 결과가 한 번만 반영되게 만들어야 합니다.
