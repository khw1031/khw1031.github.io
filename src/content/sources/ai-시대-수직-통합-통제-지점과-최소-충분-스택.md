## TL;DR
- ==전체 스택(가치사슬의 모든 계층 — 모델·인프라부터 애플리케이션·유통·서비스 운영까지)을 소유하면 이긴다는 "풀스택 승리론"은 과잉 단순화다.== 장기 우위는 이렇게 만들어진다: 고객 워크플로에서 데이터·결정·피드백이 모여 지나가는 길목(**통제 지점, control point**)을 잡으면, 제품이 쓰일수록 남이 복제하기 어려운 학습이 쌓인다. 예컨대 OpenEvidence는 "의사가 진료 중 임상 질문을 던지는 순간"이라는 길목을 잡았다 — 의학 저널은 라이선스로 빌릴 뿐 소유하지 않지만, 쓰일수록 "의사가 무엇을 어떻게 묻는가"에 대한 이해가 쌓여 콘텐츠를 가진 경쟁자도 따라오기 어렵다. 그래서 ==그 길목을 잡는 데 꼭 필요한 계층(**최소 충분 스택**)만 직접 소유하고, 나머지 계층은 빌리거나(임대·라이선스) 싸고 흔한 것으로 만들어(**범용화**) 가치가 내 길목으로 흘러오게 한다.== 창업자의 첫 질문이 "무엇을 소유할까"가 아니라 "무엇을 범용화할까"인 이유다.

## 논지 흐름
원문(Euclid VC 에세이 "Clear Eyes, Full Stack, Can't Lose?")의 논리는 여섯 단계로 전개된다.

1. **문제 제기** — 풀스택 승리론은 경제성이 다른 전략들을 하나로 묶는다.
2. **법칙** — 이익은 층 수가 아니라 성능 병목으로 흐른다 (Christensen).
3. **판별 도구 ① 소유 × 통제 2×2** — 소유와 통제 지점은 별개의 축이다 (사례 4개).
4. **판별 도구 ② 소유가 정당화되는 3조건** — 대부분의 층은 이 조건을 통과하지 못한다.
5. **전술** — 통제 지점 밖의 보완재는 범용화하되 비용 구조는 떠안지 않는다.
6. **참조점** — 1841 Mercantile Agency와 NVIDIA.

## 1. 문제 제기 — 풀스택 승리론의 과잉 단순화
AI가 소프트웨어 제작을 범용화하면서 독점 데이터·맥락·현실 피드백·신뢰·유통만 희소해졌고, 그래서 "얇은 래퍼 대신 가치사슬 전체를 소유하라"는 수직 통합론이 다시 유행한다. 저자는 절반만 동의한다: 얇은 래퍼가 취약한 것은 맞지만, "모든 것을 소유하라"는 경제성이 전혀 다른 전략들(복수 제품, 물리 자산, 하드웨어+소프트웨어, 서비스 운영)을 구분 없이 묶는 과잉 단순화다. ==AI는 실행 가능한(feasible) 경계를 넓혔을 뿐, 최적(optimal) 경계를 정해주지 않는다.== (저자 주장)

## 2. 법칙 — 이익은 층 수가 아니라 병목으로 흐른다
Christensen의 통합↔모듈화 주기가 논거의 뼈대다. 산업 초기(인터페이스 불안정, 성능 미달)에는 통합 솔루션이 신뢰성을 확보해 유리하다. 그러나 인터페이스가 표준화되면 계층별 전문화가 일어나고, 이익은 **성능을 결정하는 하위 시스템**을 통제하는 회사로 이동한다(매력적 이익 보존 법칙). 그래서 "통합은 초반에 이기고도 나중에 시장을 잃을 수 있다". AI가 바꾼 것은 실행 범위이지 이 이익 이동의 법칙이 아니다. (저자 주장)

쉬운 예가 PC 산업이다(Christensen의 고전 사례 — 이 에세이 원문에는 없음): 초기 PC는 부품 궁합이 제각각이라 IBM처럼 한 회사가 통째로 설계해야 제대로 돌아갔고, 그래서 통합 회사 IBM이 이겼다. 그런데 IBM PC의 부품 규격이 업계 표준이 되자 누구나 표준 부품을 사다 조립할 수 있게 됐고, 완성품 조립(Compaq, Dell 등)은 차별화가 사라져 마진이 떨어졌다. 이익은 여전히 성능을 좌우하던 두 부품 — CPU(Intel)와 OS(Microsoft) — 로 옮겨갔다. "인터페이스 표준화 → 조립은 범용화 → 성능 병목인 부품이 이익을 가져간다"가 매력적 이익 보존 법칙의 내용이다.

## 3. 소유 × 통제 2×2 — 사례 4개
소유와 통제 지점이 별개 축임을 보이는 것이 원문의 핵심 장치다.

| | 통제 지점 있음 | 통제 지점 없음 |
|---|---|---|
| **소유 O** | Halter | AI 네이티브 로펌 |
| **소유 X** | OpenEvidence · Abridge | 단순 래퍼 |

- **Halter — 소유가 곧 통제**: 소 목걸이 하드웨어 없이는 관찰→행동→결과 신호에 접근 자체가 불가능하므로, 소유가 통제 지점 확보의 필요조건이다. 단 하드웨어 자체는 해자가 아니다 — 해자는 관찰-행동 루프와 목축업자 워크플로이고, 1차 데이터 접근만 지키면 모듈형 부품은 시간이 지나 범용화되게 둬도 된다. (저자 주장)
- **OpenEvidence — 접근만으로 통제**: 의학 저널은 라이선스로 **접근**만 한다. 통제 지점은 "진료 시점에 의사가 임상 질문을 던지는 순간"이며, 방어력은 콘텐츠 소유가 아니라 그 질문·답변 맥락을 남보다 잘 이해하게 되는 학습에 있다. (저자 주장)
- **Abridge — 소유 없는 통제**: 센서는 마이크일 뿐이고, 통제 지점은 임상 노트의 **저작 계층(authoring layer)**이다. 노트가 Abridge에서 시작해 차팅·코딩·수익 등 후속 워크플로로 흐르므로, 필사 기술이 범용화돼도 학습은 후속 위치에서 누적된다. 단, EHR 같은 지배적 기존 기업 앞에서 이 위치가 오래 버틸지는 원문 스스로 미해결로 남긴다. (검증 필요·불확실)
- **AI 네이티브 로펌 — 통제 없는 소유**: 고객 관계·변호사·납품을 전부 사내에 두어도, 수집되는 데이터가 프런티어 모델사나 Harvey를 쓰는 기존 로펌과 다르지 않으면 차별화가 없다. "모델 개선은 경쟁 서비스가 같은 LLM 발전을 채택하지 않는 만큼만 방어력이 된다." 소유 ≠ 방어력. (저자 주장)

## 4. 소유(통합)가 정당화되는 3조건
| 조건 | 의미 | 조치 |
|---|---|---|
| 인터페이스 불안정 | 모델↔워크플로↔하드웨어 결합 방식이 계속 바뀌어 별도 벤더 간 조정 불가 | 불안정한 계층만 통합 |
| 성능이 구매자 기준 미달 | 다중 공급자 시스템이 너무 미숙해 단일 주체가 신뢰를 세워야 함 | 일시적 통합 — 지금의 배포용 통합과 미래의 방어 가능한 수익원을 구분 |
| 접근권 확보 불가 | 공급자가 데이터·센서·통합을 차단, 소유 없이는 지속 가능한 접근 불가 | 자산 직접 소유 |
| 그 외 | 안정된 표준 인터페이스 | 임대·라이선스·표준화 |

이 세 조건은 통합주의 내러티브가 암시하는 것보다 훨씬 좁고, LLM 시대에는 조건 자체가 빠르게 변한다. (저자 주장)

## 5. 전술 — 보완재는 범용화하되 비용 구조는 떠안지 않는다
첫 질문은 "무엇을 소유할까"가 아니라 **"무엇을 범용화할까"**다. 내 제품의 채택을 가로막는 보완재는 저렴·표준·풍부하게 만들어 가치가 내가 통제하는 계층으로 흐르게 한다. 단 그 인접 사업의 비용 구조를 영구히 떠안지는 않는다 — 예컨대 의료 AI 회사가 서비스 병목을 발견하면, 반복되는 서비스 작업을 통제 지점 접근으로 전환하되 저비용 서비스 업체가 되지는 말라는 것. 소프트웨어의 본질 이점은 레버리지이고, AI가 경계를 넓혔어도 자산 경량 모델의 매력은 사라지지 않았다. (저자 주장)

## 6. 두 참조점 — Mercantile Agency와 NVIDIA
- (사실) **1841 Mercantile Agency → Dun & Bradstreet**: 1837년 공황으로 신용 정보 부족이 드러나자 Lewis Tappan이 전국 통신원 네트워크로 "상인 신용 원장"이라는 정보 계층만 장악했다. 재고·창고·자본 위험(당시 수직 통합 상인들이 떠안던 것)은 소유하지 않고, 반복되는 고가치 신용 결정의 성능 병목만 소유했다. 자산 경량형 통제 지점의 원형 사례.
- (사실) **NVIDIA**: GPU 아키텍처+CUDA+네트워킹+소프트웨어 생태계는 긴밀히 통합하되, 반도체 제조는 TSMC에 맡긴다. 통제 지점(co-design)은 강화하면서 자본 집약 계층은 전문 사업자의 경제성을 빌린다 — 최대 소유가 아니라 경계선 긋기가 가치를 만든 사례.

## 결론 — 창업자용 두 질문
1. **"무엇을 범용화하려 하는가?"** — 통합 결정보다 먼저 묻는다. 보완재가 채택을 막는다면, 가격 결정력·조정 비용·신뢰성 위험을 해소하는 만큼만 통합한다.
2. **"학습이 복리로 쌓이려면 시스템의 어디에 통제가 필요한가?"** — 이 답이 곧 **최소 충분 스택**의 정의다: 통제 지점 접근을 여는 자산만 소유한다. ==장기 방어력은 소유한 층의 수가 아니라 독점적·밀도 높고 복제 어려운 학습 신호에서 나온다.==

## 확실성 구분
- **저자가 확실하다고 말한 것** — 얇은 래퍼는 취약하다; Christensen의 이익 이동 법칙은 AI 시대에도 적용된다; 수직 소프트웨어 리더들은 전체 가치사슬이 아니라 통제 지점으로 이겼다; NVIDIA는 전략적 부분 소유로 성공했다.
- **원문 스스로 미해결로 남긴 것** — 각 산업의 통제 지점이 정확히 어디인지(맥락 의존적이고 시간에 따라 이동); Abridge의 저작 계층이 EHR 기존 기업 앞에서 오래 버틸지; AI 네이티브 서비스의 장기 방어 가능성; 젊은 시장→성숙 시장 전환의 시점과 신호.

## 용어 풀이
- **Control point(통제 지점)** — 고객 워크플로에서 기록 시스템으로 확장될 수 있는 결정적 위치 / 수돗물 배관의 밸브: 물의 흐름(데이터·결정·학습)이 모이는 곳 / 비유 파열: 밸브는 고정된 물리 객체지만 통제 지점은 기술 변화에 따라 이동한다.
  - 판별식(원문에 없는 보충): **"그 순간에 내 제품이 없으면, '입력 → 선택 → 결과'가 한 줄로 기록되는 곳 자체가 사라지는가?"** — 그렇다면 그 자리가 통제 지점이다. 통제 지점은 추상적 "순간"이 아니라, 그 일이 일어나는 화면·도구 자체를 내 제품이 차지한 자리다. 아래 네 사례는 모두 원문에 없는 예시다.
  - **Google 검색** — 순간: 궁금한 것을 검색창에 치는 순간 / 지나가는 것: 쿼리 → 보여준 결과 → 무엇을 클릭 → 재검색 여부 / 쌓이는 것: "이 질문엔 이 답이 맞더라"는 판정 데이터 수십억 건 / 소유하지 않는 것: 웹 콘텐츠 전부(크롤링으로 접근만). 콘텐츠를 가진 신문사가 검색엔진을 못 만드는 이유가 이 클릭 로그의 부재다.
  - **Cursor·Copilot(AI 코드 에디터)** — 순간: 코드를 쓰다 제안을 받는 순간 / 지나가는 것: 코드 맥락 → AI 제안 → 채택·거절·수정 / 쌓이는 것: 어떤 상황에서 어떤 제안이 받아들여지는가 / 소유하지 않는 것: LLM 자체(Anthropic·OpenAI API로 임대). 모델을 가진 회사가 아니라 에디터 자리를 가진 회사에 신호가 쌓인다 — "모델은 빌리고 길목만 잡는" 최소 충분 스택의 예이기도 하다.
  - **Stripe(결제)** — 순간: 구매 버튼을 누르는 결제 순간 / 지나가는 것: 카드·금액·가맹점·기기 정보 → 승인/거절 → 사기 여부 판명 / 쌓이는 것: 수백만 가맹점을 가로지르는 사기 패턴(Radar) / 소유하지 않는 것: 은행·카드망·가맹점 상품. 개별 은행은 자기 거래만 보므로 이 교차 패턴을 못 만든다.
  - **Tmap·Waze(내비게이션)** — 순간: 운전자가 앱을 켜고 달리는 순간 / 지나가는 것: 실시간 위치·속도 / 쌓이는 것: 실시간 교통 흐름 / 소유하지 않는 것: 도로도 차도 아니고, 정적 지도 데이터는 돈 주고 살 수 있다. 흐름 데이터만은 사용 중인 앱에서만 나온다.
- **최소 충분 스택(Minimum sufficient stack)** — 학습 루프가 누적되도록 통제 지점을 잡는 데 꼭 필요한 만큼만의 소유 계층 / 요리에서 소스(간)만 직접 만들고 재료는 시장에서 산다 / 비유 파열: 소스는 대체 가능하지만 학습 신호는 대체 불가능해야 의미가 있다.
  - 자주 묻는 반문(원문에 없는 보충 — 반례는 원문 사례): "최소 충분 스택은 결국 대부분 애플리케이션 계층 아닌가?" 자주 그렇게 되지만 법칙이 아니다. 지금의 vertical AI에서는 모델·인프라가 임대 가능한 범용재가 되어 병목이 애플리케이션 표면에 걸리는 국면일 뿐이다. 신호가 물리 세계에만 있으면 하드웨어가 스택에 들어가고(Halter), 병목이 연산이면 서브시스템이(NVIDIA), 원장 자체면 데이터 계층이 들어간다(Mercantile Agency). 역으로 애플리케이션 자리를 차지해도 독점 신호가 없으면 통제 지점이 아니다(AI 네이티브 로펌). 통제 지점은 계층 이름이 아니라 **성능 병목의 위치**로 정의되고, 병목은 이동한다(PC 시대: 완성품 조립사 → Intel·Microsoft).
- **보완재(complement) 범용화** — 내 제품 가치를 높여주는 인접 자산을 풍부·표준·저렴하게 만들어, 가치(이익)가 내 통제 계층으로 이동하게 하는 전술 / 프린터 회사가 잉크로 돈을 벌 때의 반대 방향 사고 / 비유 파열: 잉크가 통제 지점이면 통용이고, 통제 지점이 다른 곳이면 잉크는 오히려 범용화 대상이다.
- **매력적 이익 보존 법칙(Christensen)** — 이익은 가장 많은 계층을 가진 회사가 아니라 성능 병목을 통제하는 회사로 이동한다는 주장 / 물의 흐름이 가장 좁은 목에서 모이는 것 / 원문에 없음: 이 법칙의 정량적 검증 여부.
