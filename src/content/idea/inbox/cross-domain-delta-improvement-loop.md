## 아이디어

도메인이 무엇이든 AI와 일하는 절차는 거의 같은 모양이다. 작업을 지시하고, 결과를 보고, 마음에 안 드는
부분을 고치고, 그 **고친 흔적(delta)** 을 다음 지시에 반영한다. 디자인 시안이든 링크드인 글이든
리팩터링이든 팟캐스트 주제 선정이든 이 골격은 바뀌지 않는다. 그런데 지금 이 루프는 매번 사람 머릿속에서
임시로 돌아가고, 델타는 채팅 로그에 흩어진 채 다음 세션으로 넘어가지 못한다. 이 아이디어는 그 루프를
**도메인·도구와 무관한 규약**으로 고정하자는 것이다. 산출물 버전, 사람이 고친 최종본, 둘 사이의 diff,
그 diff에서 뽑아낸 지시 갱신 — 이 네 가지를 표준 형태의 **델타 원장(delta ledger)** 에 누적하고,
다음 작업 지시가 항상 그 원장을 입력으로 받게 한다.

핵심은 신호의 종류다. 별점이나 순위는 사용자가 "왜 좋은지"를 어느 정도 말할 수 있어야 성립하지만,
**편집 diff는 사람이 이유를 말하지 않아도 남는다.** 고치는 행위 자체가 이미 완전한 정답 표시이기 때문에,
정상적인 작업 과정에서 신호가 공짜로 수집된다. 앞서 캡처한
[moodbox](/idea/inbox/moodbox-design-selection-loop-mcp-skill-cli/)가 N개 중 고르는 **선별 신호**를
다뤘다면, 이쪽은 하나를 고쳐놓은 **교정 신호**를 다룬다. 같은 병목의 두 가지 우회로이고, 실은 moodbox
노트의 마지막 질문("디자인 전용으로 좁힐 것인가, 루프 자체를 일반 도구로 낼 것인가")의 일반형 가지에
해당한다. 둘 다 만들 것이 아니라면 **어느 쪽이 상위 개념인지 먼저 정해야 한다.**

## 더 해볼 질문

- **이미 있는 것과 무엇이 다른가.** TextGrad는 자연어 비평을 gradient처럼 역전파하고, GEPA는 실행 트레이스를
  읽어 프롬프트를 진화시키며, user-edit에서 잠재 선호를 학습하는 연구(PROSE)도 이미 있다. 남은 빈자리가
  **연구가 아니라 일상 도구**(도메인 무관 + 로컬 + 도구 비종속)라는 가설이 참인지 먼저 확인해야 한다.
  이 질문에 답 못 하면 나머지는 의미가 없다.
- **`CLAUDE.md` 수동 관리와 실질적으로 다른가.** 지금도 사람이 규칙 파일을 손으로 고쳐 델타를 반영한다.
  자동 수집이 그 수작업보다 나은 규칙을 만드는가, 아니면 노이즈만 쌓는가.
- **일반화 가능한 델타와 일회성 델타를 어떻게 가르는가.** "이번 문장만 이렇게"와 "앞으로 항상 이렇게"는
  구분해야 한다. 잘못 일반화한 규칙은 다음 라운드를 오염시킨다. 사람이 채택/기각하는 게이트가 필요한지,
  빈도 임계로 자동 승격할지.
- **원장이 커지면 어떻게 되는가.** 델타가 수백 개 쌓이면 전부 주입할 수 없다. 요약·병합·폐기 정책이
  필요하고, 이건 규칙이 서로 모순될 때 무엇을 이기게 할지의 문제로 이어진다.
- **도메인 무관 규약이 실제로 성립하는가.** 코드의 델타는 diff로 정확히 뜨지만, 디자인 시안의 델타는
  이미지 비교이고 기획의 델타는 논지 변화다. 공통 스키마가 각 도메인에서 얄팍해지지 않는지 확인 필요.
  **한 도메인에서 먼저 통하는지 보고 확장하는 편이 안전하다.**
- **표준이라고 부를 것인가, 도구라고 부를 것인가.** 규약(스키마 + 파일 형식)만 내고 구현은 각자에게
  맡기는 길과, 실행되는 CLI/MCP를 내는 길은 채택 경로가 완전히 다르다.
- **어디서 첫 검증을 하는가.** 본 저장소의 콘텐츠 작성 자체가 좋은 시험대다 — 노트·캡처의 AI 초안과
  최종 커밋 사이 diff가 이미 git에 다 남아 있다. 새 데이터 수집 없이 과거 델타로 규칙을 뽑아
  사후 검증할 수 있는지 확인할 가치가 있다.

## 레퍼런스·서비스

확인일: 2026-08-08. 빠른 스캔이며 1차 검증은 하지 않았다.

- [Aligning LLM Agents by Learning Latent Preference from User Edits (arXiv 2404.15269)](https://arxiv.org/pdf/2404.15269)
  — 1차(원논문). 배포 중 자연히 발생하는 **사용자 편집**에서 잠재 선호를 추론해 정렬하는 PROSE 제안.
  이 아이디어의 핵심 메커니즘과 가장 정면으로 겹치는 선행 연구. 먼저 읽어야 할 한 편.
- [GEPA (gepa-ai/gepa, GitHub)](https://github.com/gepa-ai/gepa) — 1차(정본 저장소). 실행 트레이스를 읽고
  자연어 반성으로 프롬프트·코드를 진화시키는 최적화기. 델타 → 지시 갱신 단계의 기성 구현체 후보이자 경쟁자.
- [Distilling Feedback into Memory-as-a-Tool (arXiv 2601.05960)](https://arxiv.org/html/2601.05960v2)
  — 1차(원논문). 피드백을 파일 기반 메모리의 지속 가능한 지침으로 증류하는 프레임워크. "델타 원장"의
  저장·회수 설계에 직접 대응한다.
- [TextGrad 설명 (ai-tldr.dev)](https://ai-tldr.dev/learn/prompt-engineering/prompt-iteration/textgrad-textual-gradients/)
  — 2차. 자연어 비평을 gradient로 삼아 역전파하는 TextGrad의 개념 요약. 원논문 확인 전 개념 잡기용.
  **인용 시 원논문으로 대체할 것.**
- [Incremental Summarization via Progressive Note-Taking and Agent Feedback (arXiv 2510.06677)](https://arxiv.org/pdf/2510.06677)
  — 1차(원논문). 상담원의 편집을 before/after 쌍으로 로깅해 학습 신호로 쓰는 실무 파이프라인 사례.
  **"품질 개선이 확인된 쌍만 채택"** 이라는 게이트가 있어, 위 세 번째 질문의 참고 선례가 된다.
- [MemSkill: Learning and Evolving Memory Skills (arXiv 2602.02474)](https://arxiv.org/html/2602.02474v1)
  — 1차(원논문). 자기 진화 에이전트의 메모리 스킬 학습·진화. 원장 비대화·폐기 정책 질문과 연결.
  **미확인 — 제목·초록 수준만 봤다.**
- [moodbox 아이디어 (본 저장소)](/idea/inbox/moodbox-design-selection-loop-mcp-skill-cli/) — 같은 병목의
  선별 신호 버전. 범위가 겹치므로 상하 관계를 먼저 정리해야 한다.
- [YC 디자인 워크플로우 재현 캡처 (본 저장소)](/sources/yc-디자인-총괄-ai-디자인-워크플로우-재현과-선별-병목/)
  — 이 루프가 "크로스 도메인 유니버설 루틴"이라는 관찰의 출처. 화자가 링크드인 글쓰기·팟캐스트 준비에도
  같은 절차를 쓴다고 밝힌 대목.
