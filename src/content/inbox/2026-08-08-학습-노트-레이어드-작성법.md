> 캡처 맥락: 저장소의 학습 노트·스킬(what-to-learn-and-when-to-stop, learning-skill-spec, dig, core)과 원천 소스(top-down-learning, Dan Koe) 분석에 외부 근거를 더해 **종합**한 조사다. 한 저자의 논증을 옮긴 것이 아니라 조립한 것이므로, 정식 노트로 남기려면 core 스킬로 핵심을 하나씩 확정하는 절차를 따로 거친다.

## TL;DR

- 저장소는 학습 노트를 두 갈래로 못 박아 놨다 — **학습 과정 기록**(dig의 작업 시트·교환 기록)과 **완성된 개념 노트**(dig의 개념 노트, core로 확정한 notes). 여기서 다루는 "입문→전문가 통합 노트"는 후자다.
- 한 노트로 모든 층을 감당하려는 요구는 **전문성 역전 효과**와 만난다 — 초보에게 필수인 친절한 안내가 숙련자에게는 오히려 성과를 떨어뜨린다. 그래서 정답은 "모든 층을 산문에 녹이기"가 아니라 **"층을 나누되 건너뛸 수 있게 배치하기"**(progressive disclosure)다.
- 세 레이어는 서로 다른 인지 도구를 쓴다 — 입문은 은유·큰 그림, 중급은 정확한 용어와 경계·메커니즘, 전문가는 실무 사례·트레이드오프·버려진 길.
- 노트는 읽기로 끝나면 남지 않는다 — 목표(필터) + 인출(검사)이 둘 다 있어야 하고, 최소 장치는 답을 가린 확인 질문이다.

## 저장소가 이미 답한 것

| 문서 | 무엇을 규정하나 | 작성법에 주는 것 |
| --- | --- | --- |
| what-to-learn-and-when-to-stop | 학습 = 프로젝트 레이어(무엇을=목표) + 개념 레이어(어디까지=이해), 상시 지시문 10개 | 노트에 무엇을 담을지의 판정 기준 |
| learning-skill-spec | 위를 동작 규정으로 확장, 기록 다섯 산출물 | 노트가 학습의 어느 산출물인지 |
| dig 스킬 | 실제 러너. 작업 시트(질문·채점)와 개념 노트(정리된 개념)를 분리 | "과정 기록"과 "완성 노트"는 다른 문서 |
| core 스킬 | 핵심 명제 분해, 번역어+원어 병기, 명제 문체 | 완성 노트의 문장·구조 규약 |

두 가지가 핵심이다.

- **저장소는 "학습 노트"를 두 종류로 나눠 놨다.** dig은 시간순 질의응답과 개념 단위 정리를 섞지 말라고 명시한다. 이유: 시트는 시간순이라 같은 개념이 흩어지고, 흩어진 것은 다시 읽히지 않는다. 통합 노트는 개념 노트 계열이며, 과정을 쌓는 게 아니라 하강이 닫힐 때마다 정리한다.
- **dig의 응답 형식 8소제목이 이미 3층 구조다.** 한 줄 / 실측·구체 / 쉽게 / 왜 그렇게 되는가 / 가깝지만 아닌 것 / 흔히 잘못 이해하는 지점 / 없었다면 발명됐을까 / 확인 질문 — 이걸 독자 층위로 재배열하면 입문·중급·전문가로 갈린다.

## 왜 "한 노트에 다 넣기"가 함정이면서 정답인가

전문성 역전 효과: 초보에게 성과를 높이는 친절한 안내가 지식이 쌓인 학습자에게는 성과를 떨어뜨린다. 기제는 redundancy — 이미 스키마가 있는 사람은 외부 안내와 자기 지식을 대조하는 데 작업기억을 쓴다.

함의는 날카롭다. **하나의 밀도로 쓴 노트는 반드시 한쪽을 해친다.** 그래서 통합의 방법은 평균 난이도로 쓰기가 아니라:

- 층을 분리해 각 독자가 자기 층에서 멈추거나 건너뛰게 하고,
- 아래로 갈수록 깊어지게 배열해(top-down), 입문자는 위에서 멈추고 전문가는 스크롤을 내린다.

이것이 progressive disclosure이고, 문서 프레임워크로는 Diátaxis가 같은 원리를 구조화한다 — 튜토리얼(직접 해봄)·설명(이해)·레퍼런스(정확한 정보)·how-to(과제 수행)는 독자의 필요가 다르므로 섞지 말고 나눈다. 학습 노트는 대부분 "설명" 모드지만, 전문 용어는 "레퍼런스", 실무 사례는 "how-to" 성격을 띤다. 섞어 흘려 쓰면 세 독자를 다 놓친다.

독자 층위의 골격은 Dreyfus 5단계로 잡는다 — novice(규칙을 따름) → advanced beginner → competent(계획·판단) → proficient → expert(사례로 직관 판단). 초보는 규칙과 맥락 없는 정의가 필요하고, 전문가는 사례·트레이드오프·예외가 필요하다.

## 레이어별 구성 요소

### 레이어 1 — 입문 (직관·동기): "왜 있고 대충 뭔가"

- **한 줄 결론 + 문제·동기.** 왜 필요한지 먼저. 목표가 없으면 필터가 없어 아무것도 안 남는다(Dan Koe의 사이버네틱 학습).
- **큰 그림 다이어그램.** 부분들이 어떻게 맞물리는지 한눈에.
- **12살 눈높이 은유.** 전문 용어로 포장하면 용어를 되풀이할 수 있다는 이유로 안다는 착각이 생긴다.
- **돌아가는 최소 전체 하나.** 완성된 작은 예시를 먼저 손에 쥐여준다(동작 → 라인 → 부품 순서).

### 레이어 2 — 중급 (정확성·어휘): "정확히 뭐고 왜 그렇게 되나"

- **정확한 정의 + 전문 용어 병기.** 번역어 앞, 첫 등장에 원어를 괄호로. 예) 잔차 연결(residual connection). 이게 있어야 독자가 검색·검증하며 전문가 층으로 건넌다.
- **정의와 이유를 분리.** 정의에서 멈추지 말고 이유까지. 다음 질문은 이유 쪽에서만 나온다.
- **가깝지만 아닌 것 하나.** 한 가지만 다르고 나머지는 같은 대조쌍으로 개념 경계를 긋는다. 예) autoencoder와 VAE, batch norm과 layer norm.
- **중간 상태·shape·수치.** shape가 빠지면 추측이 확인으로 바뀌지 못한다. 분포는 수식 말고 그래프로.
- **흔한 오해 + 왜 그렇게 오해하나.** 지금 하는 오해는 스스로 지목하지 못한다.

### 레이어 3 — 전문가 (판단·맥락): "실무에서 어떻게 쓰고 언제 안 쓰나"

- **실무 사례.** 실제 시스템·코드에서 어떤 값·설정으로 쓰이는지. 전문가는 규칙이 아니라 사례로 판단한다.
- **트레이드오프와 실패 모드·edge case.** 언제 안 맞나, 무엇이 깨지나(Dan Koe 노트의 용어 풀이 "깨짐:" 형식이 본보기).
- **대안과 버려진 길.** 무엇이 정답인가보다 왜 다른 길이 버려졌나가 이해에 더 기여한다.
- **없었다면 발명됐을까.** 다시 발명될 것이면 필수 요소, 아니면 역사적 관행.
- **1차 출처.** 심화·검증 진입점. 링크마다 한 줄 요약 + 1차/2차 + 확인 날짜.

## 한 노트에서 레이어를 물리적으로 배치하는 법

저장소의 top-down-learning 소스 노트가 이미 이 구조를 쓴다. 일반형:

```text
제목 + 한 줄 명제            ← 입문: 스크롤 안 내려도 결론이 잡힌다
## 큰 그림 (다이어그램)        ← 입문: 전체 맞물림
## 핵심 (산문)               ← 입문→중급: 은유에서 메커니즘으로
## 깊이                      ← 중급→전문가: 소절마다 필수/곁가지 표시
## 용어 풀이                  ← 중급: 번역어(원어) + "깨짐:" 한 줄
## 확인 질문 (답 가림)         ← 검증 장치
## 레퍼런스 (1차/2차·날짜)      ← 전문가: 심화 진입점
```

배치 원칙 셋:

1. **위에서 아래로 깊어지게.** 입문자는 큰 그림·핵심에서 멈추고 전문가는 깊이·레퍼런스로 내려간다. 아무도 자기에게 불필요한 층을 강제로 읽지 않아 전문성 역전을 피한다.
2. **층을 시각적으로 표시해 건너뛰게 하라.** 소절 표식이나 소제목("쉽게" / "깊이" / "실무")으로. 모드를 섞으면 그 순간 그 독자를 놓친다.
3. **용어는 병기, 사례는 격리.** 전문 용어는 번역어(원어)로 정의하고, 실무 사례·예외는 별도 소절로 모아 입문 독자의 흐름을 끊지 않게.

## 노트가 실제로 학습을 남기게 하는 장치

레이어를 잘 나눠도 읽기만 하면 남지 않는다.

- **인출 연습을 내장.** 학습 기법 10개 중 practice testing과 distributed practice만 high utility 등급(Dunlosky 2013). 노트 끝에 답을 가린 확인 질문 3개, 그중 하나는 설명에 없던 상황에 적용.
- **스스로 답을 만들게.** 읽은 정보보다 스스로 생성한 정보가 더 남는다(생성 효과, d≈.40). 답을 다 떠먹이지 말고 질문으로 남길 자리를 둔다.
- **쉬운 느낌을 경계.** 지금의 수행과 남는 학습은 다르고, 쉽게 느껴지는 조건이 오래 남는 것을 줄인다(Bjork). 이해된 느낌으로 노트를 닫지 않는다.

반론 하나: Dan Koe는 인출을 input 모델의 증상으로 묶어 기각하지만, 필터와 인출은 배타적이지 않다. 목표(필터)는 무엇을 배울지 정하고 인출은 그게 진짜 남았는지 검사한다. 필터만 있고 검사가 없으면 이해했다는 착각이 조용히 굳는다.

## 흔한 실패 (안티패턴)

| 신호 | 무엇이 무너지나 | 교정 |
| --- | --- | --- |
| 평균 난이도로 뭉갬 | 전문성 역전 — 초보·전문가 둘 다 놓침 | 층 분리 + 위→아래 심화 |
| 시간순 질의응답을 그대로 쌓음 | 같은 개념이 흩어져 다시 안 읽힘 | 개념 단위로 정리(하강 닫힐 때) |
| 정의로 끝냄 | 다음 질문이 안 생김 | 정의 뒤에 "왜 그렇게 되는가" |
| 전문 용어를 번역어로만 씀 | 검색·검증 불가, 전문가 층 단절 | 번역어(원어) 병기 |
| 확인 질문 없음 | 읽고 이해된 느낌만 남고 인출 안 됨 | 답 가린 질문 3개 |
| 사례 없이 개념만 | 전문가 층이 비어 판단에 못 씀 | 실무 사례 + 트레이드오프 + 언제 안 쓰나 |

## 한계

- 이 통합 구조는 완성된 개념 노트에만 맞는다. 진행 중 세션의 날것 기록은 별도 산출물이며 섞으면 안 된다.
- 레이어 경계는 독자가 정하지 저자가 완벽히 못 정한다. 입문/중급의 선은 독자의 사전 지식에 따라 움직인다(전문성 역전이 말하는 그 지점). 표식으로 건너뛸 여지를 주는 것이 최선이다.
- 인용 수치(생성 효과 d≈.40 등)는 각 실험 조건의 값이고, 산문형 개념 노트에 그대로 이식된다는 보장은 없다.

## 재사용 템플릿

새 학습 노트를 쓸 때 아래 골격을 복사해 채운다. 각 소제목 옆 대괄호는 그 층이 요구하는 것이다.

```markdown
---
title: '{대상}의 {다루는 범위} {문서 종류}'
pubDate: '{YYYY-MM-DDThh:mm:ss+09:00}'
description: '{한 줄. 이 노트가 무엇을 설명하는가}'
summary: '{독립적으로 읽히는 짧은 초록}'
lang: ko
tags: ['learning', '{주제}']
---

> 한 줄 명제: {스크롤 안 내려도 결론이 잡히는 한 문장}

## 큰 그림
[입문] {부분들이 어떻게 맞물리는지 다이어그램 한 개. 단일 관계면 ASCII, 다중 관계면 mermaid}

## 핵심
[입문→중급] {12살 눈높이 은유로 시작해 메커니즘으로 내려간다. 돌아가는 최소 전체 예시 하나}

## 깊이
[중급→전문가] {소절로 나누고 필수/곁가지를 표식으로 구분}
- 정의와 이유를 분리한다 (정의에서 멈추지 않는다)
- 가깝지만 아닌 것 하나로 경계를 긋는다
- 중간 상태·shape·수치를 구체로 보여준다
- 실무 사례: 실제로 어떤 값·설정으로 쓰이나
- 트레이드오프·실패 모드·edge case: 언제 안 쓰나
- 대안과 버려진 길, 왜 버려졌나
- 없었다면 발명됐을까 (필수 요소 vs 역사적 관행)

## 용어 풀이
[중급] {번역어(원어) — 한 줄 정의 / 깨짐: 이 개념이 흔들리는 지점}

## 확인 질문
```
