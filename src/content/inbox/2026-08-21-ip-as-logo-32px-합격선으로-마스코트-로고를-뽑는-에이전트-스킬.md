## TL;DR
- ip-as-logo는 "32px에서 읽히는가"를 유일한 합격선으로 삼아, 마스코트 로고를 자동으로 뽑되 못 쓸 그림을 미리 걸러내는 에이전트 스킬이다.

## 큰 그림
```
[ip-as-logo 스킬 구조]

  레포 내용: 코드 ✕ → 문서 1장 (프롬프트/규칙서)
       │
       ▼
  ┌─ 실행 순서 ─────────────────────────┐
  │ ① 제품 설명 읽기 (맥락 파악)        │
  │ ② 로고 도형 먼저 설계               │
  │ ③ 캐릭터는 그 다음에 얹기           │
  │ ④ 후보 6장 일괄 생성               │
  └────────────────────────────────────┘
       │
       ▼
  합격 판정: 32px 축소 시 가독성
       │
       ├─ 통과 → 앱 아이콘·파비콘 그대로 사용
       └─ 탈락 → 재생성 (뭉개짐 방지)
```

## 핵심
이 스킬의 출발점은 단순한 관찰이다. GPT에게 "마스코트 그려줘"라고 하면 그럴듯한 그림이 나오지만, 앱 아이콘이나 파비콘 크기로 줄이는 순간 털·장식·세부 선이 뭉개져 형체를 잃는다. 저자는 이 문제를 해결하기 위해 **합격선을 32px 가독성 하나로 고정**했다. 이 한 줄이 나머지 모든 제약(도형 수, 색 수, 선 굵기, 배치)을 연역적으로 끌어낸다. 즉 "예쁜 그림 생성기"가 아니라 "작은 크기에서 못 쓸 그림을 사전에 제거하는 필터"로 설계된 것이 기존 로고 생성 도구와의 차이점이다.

## 깊이
- **[합격선 → 제약 도출]** 32px에서 읽히려면 그릴 수 있는 요소가 물리적으로 줄어든다. 그래서 도형 6~10개, 색 최대 3개(캐릭터 2 + 배경 1)로 상한을 못박는다. 뾰족한 끝(귀·뿔·꼬리)은 전부 뭉툭하게 처리하는데, 얇은 선·뾰족한 끝이 축소 시 가장 먼저 사라지기 때문이다.
- **[배치 전략]** 캐릭터를 중앙에 얌전히 놓지 않고 아래 모서리에서 올라오게 배치해 화면의 약 80%를 채운다. 잘려 나가는 것은 의도이며, 이는 실제 앱 아이콘이 원형 마스킹으로 잘리는 상황을 반영한다.
- **[얼굴 단순화]** 눈 둘 + 입 하나만 남기고 눈썹·콧구멍 등 미세 요소는 제거한다.
- **[실행 조건]** 이미지 생성 기능이 있는 AI에서만 동작하며, 없으면 "먼저 켜달라"고 요청한다. 만든 이가 미리 뽑아둔 로고를 사이트에서 고를 수도 있고, 상업적 사용도 허용되어 있다.

## 용어 풀이
- **에이전트 스킬** — AI 에이전트에 끼워 넣는 "행동 설명서". 비유: 요리사에게 건네는 레시피 카드. 다만 레시피와 달리 재료(이미지 생성 API)가 없으면 요리 자체를 거부한다는 점이 다르다.
- **32px 가독성** — 파비콘·앱 아이콘 최소 표시 크기. 비유: 명함을 1 cm 크기로 줄였을 글자가 읽히는가. 다만 실제 파비콘은 브라우저·OS별 렌더링 차이가 있어 32px 하나만으로 완전 보장되진 않는다.

## 시각 자료
| 제약 항목 | 규칙 | 이유 |
|---|---|---|
| 도형 수 | 6~10개 | 축소 시 형태 유지 |
| 색 | 최대 3 (캐릭터2+배경1) | 뭉개짐 방지 |
| 선/끝 | 뾰족 금지, 뭉툭하게 | 얇은 선 소실 |
| 배치 | 하단→상승, 80% 차지 | 원형 마스킹 대응 |
| 얼굴 | 눈2+입1만 | 미세 요소 제거 |
