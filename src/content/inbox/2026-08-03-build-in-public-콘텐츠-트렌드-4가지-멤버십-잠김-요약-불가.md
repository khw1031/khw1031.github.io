## TL;DR
- 본문이 **멤버십 잠김** 상태여서 제목과 티저 외에 핵심 정보(4가지 콘텐츠 유형)를 확인할 수 없다.

## 큰 그림

```
[뉴스레터: 요즘 떡상하는 Build in Public 콘텐츠 4가지]
 │
 ├─ 티저 (공개)
 │   ├─ "요즘 많이 보이는 패턴"
 │   ├─ "오래 갈 것 같은 유행"
 │   └─ "저 정도면 나도 할 수 있을지도?"
 │
 ├─ 본문 4가지 유형 (🔒 멤버십 잠김 — 원문에 없음)
 │
 └─ 출처 표기: "나의 뇌 + 약간의 자료 조사" (저자 주관 정리)
```

## 핵심
- 이 뉴스레터는 **Build in Public**(제품 개발 과정을 공개하며 팬덤·피드백을 동시에 얻는 전략) 콘텐츠 중 최근 주목받는 4가지 유형을 소개하겠다고 예고한다.
- 그러나 Jina로 크롤링한 입력에는 **공개 티저와 주변 내비게이션(이전/다음/다른 뉴스레터 목록)만 포함되어 있고**, 핵심 본문은 멤버십 유료 전환(발행 24시간 후 자동 잠김)으로 접근할 수 없다.
- 따라서 4가지 콘텐츠 유형이 무엇인지, 각 유형의 특징·장단점·사례는 **원문에 없음**으로 처리할 수밖에 없다.

## 깊이
- **[공개 정보의 한계]** 티저 세 문장에서 저자의 큐레이션 기준을 유추할 수 있다: ①최근 빈도 증가(패턴), ②지속 가능성(유행), ③진입장벽 낮음(나도 할 수 있을지도?). 그러나 이것이 4가지 유형과 어떻게 매핑되는지는 **불확실**.
- **[주변 정보로 미루어 본 맥락]** 같은 뉴스레터의 다른 호에서는 "API를 활용한 돈 되는 서비스 아이디어", "잘 나가는 앱 베끼는 방법(TrustMRR·Ahrefs 활용)", "1인 개발자 디자인 가이드", "선 개발 후 디자인 시스템" 등을 다루고 있어, 발행자가 **1인 개발·사이드 프로젝트 수익화**에 집중하는 채널임을 알 수 있다.
- **[저자 주장의 성격]** 출처를 "나의 뇌 + 약간의 자료 조사"라고 명시했으므로, 이 글은 데이터 기반 분석이 아닌 **저자의 주관적 큐레이션**이다(2차자료 성격 재확인).

## 용어 풀이
- **Build in Public** — 제품·서비스를 만드는 과정을 SNS·블로그 등에 실시간 공개하는 방식 / 비유: "요리 과정을 라이브로 보여주며 손님과 함께 메뉴를 개선하는 식당" / 비유가 깨지는 지점: 요리 라이브는 실시간 소통이지만, Build in Public은 비동기 피드백이 주를 이루며, 관객이 반드시 고객이 되지는 않는다.
- **멤버십 전환** — 발행 후 일정 시간(여기서 24시간)이 지나면 무료 열람이 차단되고 유료 구독자만 읽을 수 있는 구조.

- **(저자 주장)** Build in Public 콘텐츠 중 "요즘 많이 보이고, 오래 갈 것이며, 진입장벽이 낮은" 4가지 유형이 존재한다. — **불확실**(본문 확인 불가).
