## TL;DR
- ==엔지니어링 매니저는 기술 역량보다 관계 관리, 감정 통제, 비즈니스 이해, 자기 학습이 더 중요한 외롭고 책임 큰 역할이다.==

## 큰 그림
```
엔지니어링 매니저의 역할 전환
│
├─ 관계 변화
│  ├─ 팀과의 거리감 발생 (더 이상 동료 아님)
│  ├─ 말 한마디가 지시로 해석됨
│  └─ 공유 불가 정보로 인한 고립
│
├─ 감정 관리
│  ├─ 퇴근 후에도 이어지는 스트레스와 반추
│  ├─ 폭풍 속 침착함 유지 (역할 모델)
│  └─ 무력감 속 팀의 중심 지키기
│
├─ 역량 확장
│  ├─ 기술 → 비즈니스 이해 (KPI, 전략)
│  ├─ 피드백 (명확성 + 신속성)
│  ├─ 상향 관리 (상사의 성공 지원)
│  └─ 조직 전체 조감도 (의존 관계, 구조적 문제)
│
└─ 자기 개발
   ├─ 회사 교육 부재 → 스스로 학습
   ├─ 멘토·동료 매니저 네트워크
   └─ 노동법·인사 제도 기초 지식
```

## 핵심
- 엔지니어에서 매니저로 전환하면 **기술 업무보다 관계와 감정이 핵심**이 된다. 팀과의 관계는 근본적으로 달라지고, 가벼운 말도 지시로 받아들여지므로 언어와 태도를 의식적으로 관리해야 한다.
- 매니저 업무는 **성과가 수주에 걸쳐 나타나므로**, ==회의와 잡무에 매몰되지 않고 명확한 목표를 세워 진척을 직접 추적해야 한다.==
- 대부분 회사는 매니저 교육을 제공하지 않으므로, 피드백·노동법·비즈니스 이해·상향 관리를 **스스로 학습**하고 동료 매니저와 멘토 네트워크를 구축해야 한다.

## 깊이
- **관계 변화**: 매니저가 되면 팀은 사적 대화를 나누고 매니저를 뒤에서 이야기한다. 첫 연봉 협상이나 어려운 결정 이후 거리감이 명확해지며, 예전 동료 관계를 그리워하게 된다(저자 주장).
- **피드백**: 많은 매니저가 불편함을 피해 명확한 피드백을 미루고, 그 결과 역기능적 행동이 굳어진 팀을 물려받게 된다. ==나쁜 행동을 방치하면 팀 전체가 인식하므로 신속한 대응이 필요하다==(저자 주장).
- **상향 관리**: 《The Staff Engineer's Path》에 따르면 상사의 우선순위를 이해하고 필요한 정보를 제공하며 장애물을 해결하는 것이 상향 관리다. 상사의 성공은 사회적 자본을 만들고, 이는 다시 자신에게 도움이 된다(2차 인용).

## 용어 풀이
- **상향 관리(Managing Up)** — 상사를 돕는 기술 / 비유: 상사의 성공을 위한 백그라운드 프로세스 / 깨지는 지점: 상사의 모든 업무를 대신하는 것이 아님
- **역기능적 행동** — 팀의 생산성을 해치는 습관 / 비유: 느리게 퍼지는 버그 / 깨지는 지점: 개인 성격 문제가 아닌 시스템 문제일 수 있음
- **Jantelagen** — 스웨덴 문화로, 자신을 드러내지 않는 규범 / 비유: "나눠 먹기" 문화 / 깨지는 지점: 팀 성과 홍보와 충돌
