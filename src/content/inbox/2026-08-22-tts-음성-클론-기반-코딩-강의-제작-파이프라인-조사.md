## 조사 범위

내 목소리를 클론한 TTS와 코딩·AI 주제를 결합해 **인프런 강의와 유튜브 영상을 제작**하기 위한 방법론을 정리한다. 특히 React·HTML로 영상을 만드는 방식(프로그래매틱 비디오)을 어디까지 쓸 수 있는지에 초점을 둔다.

핵심 결론부터: **이 조합은 잘 맞는다.** TTS 내레이션의 최대 약점인 재녹음 비용이 프로그래매틱 영상과 결합하면 최대 강점으로 뒤집히기 때문이다. 다만 React로 영상을 *전부* 만들려 하면 실패한다.

출처 신뢰도는 갈린다. Remotion 라이선스 FAQ와 인프런 지식공유자 가이드는 1차 출처로 직접 확인했고, 완주율·레슨 길이 통계는 플랫폼 마케팅 자료라 방향성 참고용이다.

## 권장 스택

```text
대본        MDX 단일 파일 (진실원 하나)
   ↓
음성        ElevenLabs PVC (내 목소리 클론) → scene별 wav
   ↓
정렬        whisper.cpp --dtw → 단어 단위 타임스탬프
   ↓
영상        Remotion — 씬 길이를 wav 길이에서 자동 계산
   +        Screen Studio 화면녹화 (실습 구간만)
   +        shiki-magic-move / Code Hike (코드 애니메이션)
   ↓
출력        16:9 인프런 / 9:16 유튜브 숏폼 — 같은 소스에서 두 컴포지션
```

## React로 영상: 어디까지 쓰고 어디서 멈추나

가장 중요한 판단 지점이다. Remotion으로 전부 만들려는 시도는 거의 항상 실패한다.

| 구간 | 도구 | 이유 |
|---|---|---|
| 인트로·아웃트로·챕터 전환 | **Remotion** | 100개 레슨에 일관 적용, 브랜딩 수정이 1커밋 |
| 개념 설명 슬라이드·다이어그램 | **Remotion** | JSX와 CSS로 작성, 대본 수정 시 자동 재렌더 |
| 코드 변화 설명 | **shiki-magic-move / Code Hike** | diff 기반 애니메이션 |
| 아키텍처·데이터 흐름 애니메이션 | Remotion 또는 Motion Canvas | 손으로 다듬는 애니메이션이면 Motion Canvas가 편함 |
| **실제 IDE 조작·터미널 실행·디버깅** | **화면 녹화 (Screen Studio)** | Remotion으로 재현하면 10배 느리고 진짜가 아님 |
| 브라우저 결과 확인 | 화면 녹화 | 동일 |

Remotion의 모델은 `useCurrentFrame()` 훅으로 **각 프레임을 시간의 함수**로 쓰는 것이다. 키프레임 커브가 아니라 코드라서, 대본이 바뀌면 영상이 따라 바뀌는 파이프라인을 만들 수 있는 게 본질적 이점이다.

### 프로그래매틱 영상 도구 비교

| 도구 | 주간 다운로드 | 성격 | 판단 |
|---|---|---|---|
| **Remotion** | 약 60K | React 컴포넌트가 곧 영상 | React 강의라면 이것 |
| Motion Canvas | 약 8K | TypeScript 제너레이터, 실시간 에디터 | 손으로 다듬는 설명 애니메이션에 최적 |
| Revideo | 약 3K | Motion Canvas 포크 + 렌더 API | 자동화 파이프라인 지향 |

React 기반 강의를 만든다면 Remotion이 명백하다 — 강의 소재와 제작 도구가 같은 언어라 **강의 자체가 도구의 데모**가 된다.

### 라이선스 (1차 출처 확인)

공식 FAQ 기준으로 **개인, 3명 이하 조직, 비영리는 무료**이며 상업적 사용을 포함한다. 유료 강의 영상을 Remotion으로 만들어 판매하는 것은 문제없다. 금지되는 것은 Remotion 자체를 제품으로 재판매하거나, 사용자가 임의 Remotion 코드를 제출해 렌더링하게 하는 경우다. 4명 이상 조직은 seat당 월 25달러.

## TTS: 내 목소리 클론

### 클론 등급

| 방식 | 필요 음성 | 강의용 판단 |
|---|---|---|
| Instant Voice Clone (IVC) | 1~3분 클린 모노, 22kHz 이상 | 프로토타입용 |
| **Professional Voice Clone (PVC)** | **최소 30분, 권장 3시간** 스튜디오급 | **강의는 이쪽** |

수십 시간짜리 강의를 만들 거면 PVC가 맞다. 초기 3시간 녹음이 아깝게 느껴지지만, 이후 **대본 수정 시 재녹음이 0원**이 되는 것이 전체 제작에서 가장 큰 레버리지다. Eleven v3가 한국어를 지원하고 오디오 태그로 감정·호흡 제어가 된다. 단 v3는 실시간이 아니며 요청당 5,000자 제한이 있다.

Creator 티어 월 22달러(10만 자)에서 PVC를 쓸 수 있고, 강의 분량이면 Pro 월 99달러(50만 자)가 현실적이다.

한국어 대안으로 타입캐스트가 한국어 유튜브 내레이션에 특화돼 있으나, "내 목소리"가 요구사항이면 PVC 품질에서 ElevenLabs가 앞선다.

### 강의 TTS의 실제 함정

일반 내레이션과 다른 문제가 셋이다. 준비 없이 시작하면 여기서 가장 많이 깨진다.

1. **기술 용어 발음** — `useEffect`, `props`, `nullish`, `SIGTERM`, `k8s`, `PostgreSQL`. 한국어 TTS는 이것을 예측 불가능하게 읽는다. **발음 사전을 대본 파이프라인 초입에 두고**, 대본에는 `useEffect`로 쓰되 TTS 입력에는 `유즈이펙트`로 치환하는 레이어를 넣는다. 이 치환 테이블이 강의 자산이 된다.
2. **한영 혼용 억양** — "이 컴포넌트는 state를 가집니다" 같은 문장에서 끊긴다. 문장 설계 단계에서 코드 식별자를 문장 끝이나 쉼표 뒤로 배치하는 것이 실효가 크다.
3. **숫자와 기호** — `0.1`, `<T>`, `=>`. 명시적으로 풀어 쓰거나 치환한다.

## 파이프라인 설계 — 핵심 기법

가장 중요한 설계 원칙은 하나다.

> 씬 길이를 손으로 정하지 말고 **렌더된 wav 길이에서 계산**한다.

수동 프레임 카운팅을 없애는 것이 이 파이프라인의 전부다. 실제 동작하는 Remotion 파이프라인 구현체들이 공통으로 쓰는 방식이 "TTS → 정렬 → 메타데이터 빌드 → Remotion 렌더"를 원커맨드로 묶고 슬라이드 길이를 실제 WAV 길이에서 계산하는 것이다.

```text
lesson-03.mdx                      ← 대본 + 씬 정의 (진실원)
   │
   ├─ 1. 발음 치환 → TTS 입력 텍스트
   ├─ 2. ElevenLabs API → scene-01.wav, scene-02.wav, ...
   ├─ 3. whisper.cpp --dtw → 단어 단위 startMs/endMs
   ├─ 4. build-metadata → { sceneId, durationInFrames, captions[] }
   └─ 5. remotion render → lesson-03.mp4 (16:9) + lesson-03-short.mp4 (9:16)
```

3단계의 `--dtw` 플래그가 중요하다. 이것이 없으면 타임스탬프가 실제로 정확하지 않다. Remotion은 `startMs`/`endMs`를 가진 표준 `Caption` 타입을 제공하고 `@remotion/install-whisper-cpp`로 transcribe를 붙일 수 있어, 단어 단위 하이라이팅 자막까지 그대로 나온다.

**이 구조가 만드는 것**: 대본 한 문장을 고치면 그 씬의 wav만 재생성되고, 그 씬의 duration만 바뀌며, 영상 전체가 자동으로 다시 맞는다. 사람 목소리 녹음이면 스튜디오를 다시 잡아야 하는 수정이 커밋 하나가 된다. **TTS와 프로그래매틱 영상은 이 지점에서 서로를 필요로 한다.**

### 한 소스에서 두 플랫폼

Remotion은 같은 소스에서 여러 컴포지션을 렌더한다. 인프런용 16:9 풀 레슨과 유튜브 숏폼 9:16을 대본 하나에서 뽑을 수 있으므로, 유튜브를 인프런 강의의 유입 채널로 쓰는 전략이 추가 제작비 거의 없이 성립한다.

## 코드 화면 도구

| 도구 | 방식 | 쓸 자리 |
|---|---|---|
| **shiki-magic-move** | 텍스트 diff와 FLIP 애니메이션. React·Vue·Svelte 래퍼 | 코드가 A에서 B로 변하는 과정 |
| **Code Hike** | AST 파싱 기반 focus·motion·interactivity, MDX 매직 코멘트로 제어 | 긴 코드에서 특정 줄로 시선 유도 |
| **Slidev** | shiki-magic-move 내장 | 슬라이드 중심 강의면 Slidev 녹화도 선택지 |
| **Screen Studio** | 자동 줌·모션 블러 화면 녹화 (macOS 전용) | 실습 구간. 별 노력 없이 프로급 결과 |

Remotion 안에 shiki-magic-move를 React 컴포넌트로 넣는 조합이 가장 자연스럽다. 코드 변화 애니메이션이 대본 타임라인에 붙는다.

## 강의 설계 방법론

프로덕션보다 여기가 완주율을 결정한다.

- **레슨 길이 5~12분, 한 레슨 한 개념.** 설명 중심은 6~12분, 실습 포함은 12~20분. 학습형 영상 시청 유지율 최고 구간은 10~15분
- 45분 교육을 6분씩 6개로 쪼갰더니 완주율이 52%에서 89%로 올랐다는 사례가 있다
- 온라인 강의 평균 완주율은 5~15%. 활발한 토론이 있는 강의는 65.5%, 없으면 42.6% — **완주율의 최대 구조적 변수는 콘텐츠가 아니라 상호작용**이다. 인프런 질문 게시판 운영을 제작 계획에 포함해야 한다
- 프레임워크: 진척을 보이게(Progress), 정보보다 행동(Action), 전부 쪼갤 것(Chunks), 감정 여정 인정(Emotional)

TTS 파이프라인은 여기서도 유리하다. 레슨을 쪼개고 재배치하는 리팩터링이 파일 이동 수준이 된다.

## 플랫폼 요건과 리스크

### 인프런 (공식 가이드 확인)

- **TTS 허용** — "텍스트 음성 변환(TTS) 서비스를 활용하실 수는 있어요". 단 "지식공유자의 목소리를 직접 녹음하시는 걸 제일 권해드려요"라고 명시. 내 목소리 클론이면 이 권고의 취지에 부합한다
- **빈 오디오 트랙 필수** — 무음 영상이라도 오디오 트랙이 없으면 인프런 강의실 플레이어에서 재생되지 않는다. Remotion 렌더 설정에서 반드시 확인
- **자막은 인프런이 AI로 자동 생성**하며 지식공유자 직접 등록 기능은 제공하지 않는다. 정확한 대본을 갖고 있어도 올릴 수 없다. 발음이 뭉개지면 자동 자막도 틀리므로 **발음 사전 관리가 자막 품질에도 직결**된다
- 커리큘럼 일괄 업로드는 한 번에 최대 20개 수업
- 강의 공개 심사는 영업일 기준 최대 7일
- 해상도·코덱·용량 제한은 공개 가이드에 명시가 없다. 첫 레슨으로 테스트 업로드해 확인해야 한다

### 유튜브

- **합성 콘텐츠 공시 의무** — 합성 음성이 들어가면 업로드 시 "altered or synthetic content"를 체크한다. 공시 자체는 수익화를 제한하지 않지만 반복적 미공시는 파트너 프로그램 정지 사유다
- 2026년 'repetitious content'가 **'inauthentic content'로 개명**되며 범위가 넓어졌다. 다만 정책이 문제 삼는 것은 남이 만든 자료를 그대로 읽는 채널이고, **본인이 조사·작성·편집한 원본 대본을 합성 음성이 읽는 것은 명시적으로 다른 것**으로 구분한다. 직접 쓴 기술 강의는 안전 범위다
- 안전선: 대본 원본성 + 연출된 내레이션 + 제대로 된 믹싱

## 실행 순서

1. **파일럿 1편** — 5분짜리 레슨 하나를 IVC(1~3분 음성)로 끝까지 관통한다. 도구 검증이 목적이지 품질이 목적이 아니다
2. **인프런 테스트 업로드** — 코덱·오디오 트랙·자동 자막 품질을 실측한다
3. **PVC 녹음** — 파일럿에서 나온 발음 문제를 반영한 스크립트로 3시간 녹음
4. **파이프라인 고정** — MDX 스키마, 발음 치환 테이블, Remotion 씬 컴포넌트 라이브러리, 원커맨드 빌드
5. **커리큘럼 확정 후 양산** — 여기서부터 편당 비용이 급락한다

## 확인이 필요한 항목

1. **인프런 영상 기술 스펙** — 공개 가이드에 해상도·코덱·용량이 없다. 테스트 업로드 또는 문의 필요
2. **PVC 한국어 품질** — v3가 한국어를 지원한다는 것과 내 목소리 한국어 클론이 강의 수준으로 자연스러운가는 다른 문제다. 최소 분량 30분으로 먼저 검증할 것
3. **완주율·레슨 길이 수치** — 대부분 코스 플랫폼 마케팅 자료다. 방향은 신뢰할 만하나 절대값은 아니다
