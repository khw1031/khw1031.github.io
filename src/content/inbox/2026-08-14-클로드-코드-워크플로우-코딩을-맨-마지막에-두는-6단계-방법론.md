## TL;DR
- AI 코딩 도구는 "코드부터 쓰게" 하면 실패한다. 맥락 이해 → 계획 → 승인 → 코딩 순으로遅춰야 정확도가 올라간다.

```
[Anthropic의 클로드 코드 워크플로우]

  ①탐색 ──▶ ②계획 ──▶ ③승인 ──▶ ④코딩 ──▶ ⑤검증 ──▶ ⑥커밋
  (구조이해)  (수정안)  ( human gate) (작성)  (자가수정)  (규칙저장)

     └──── "코딩은 맨 마지막" ──── 맥락 누적 ──────┘
                    │
              CLAUDE.md (반복 규칙 저장소)
```

## 핵심
- 이 워크플로우의 출발점은 **"AI가 코드베이스를 이해하지 못한 상태에서 코드를 쓰면 결과가 산으로 간다"**는 문제의식이다. 그래서 첫 단계에서 코드 작성 대신 코드베이스 구조를 먼저 읽힌다(①탐색). 구조를 파악한 AI에게 수정 계획을 먼저 요구하면(②계획), 인간은 실제 코드 변경 전에 방향성만 검토할 수 있다. 계획이 승인된 후에만(③승인) 코드를 작성하게 하는 이유는, AI가 자율적으로 잘못된 경로를 선택하는 것을 human gate로 차단하기 위해서다. 코딩 이후에는 AI 스스로 테스트·스크린샷으로 결과를 검증하게 하고(⑤검증), 반복되는 패턴은 CLAUDE.md에 저장하여(⑥커밋) 다음 세션에서 ①탐색 비용을 줄인다.

## 깊이
- **[①탐색—맥락 로딩]** 코드베이스 구조를 AI에게 먼저 이해시키는 단계. Anthropic은 이 과정을 통해 신입 온보딩 기간이 2~3주에서 2~3일로 단축되었다고 **주장**한다. (검증 필요: 구체적인 측정 기준·샘플 불명)
- **[③승인—Human-in-the-loop]** "내 승인 전엔 코드 쓰지 마"는 AI agent의 자율성을 의도적으로 제한하는 패턴. agentic coding에서 권한 위임과 통제 사이의 긴장을 해결하는 한 방식이다.
- **[⑥커밋—CLAUDE.md]** 반복 규칙을 파일로 저장하면 다음 세션의 ①탐색 단계가 단축되는 일종의 "기관 기억(institutional memory)" 역할을 한다. 이는 context window 한계를 보완하는 실용적 전략이다.

## 용어 풀이
- **CLAUDE.md** — Claude Code가 프로젝트 시작 시 읽는 설정 파일 / 비유: 신입사원에게 주는 사내 위키 / 비유가 깨지는 지점: 위키와 달리 AI가 자동으로 참조하므로 최신화가 더 치명적.
- **Human gate** — AI agent 파이프라인 중간에 인간 승인 단계를 두는 것 / 비유: 공장 품질검사 정류장 / 비유가 깨지는 지점: 병목이 생겨 속도 이점이 줄어듦.
- **바이브 코딩(vibe coding)** — AI에게 자연어로 지시하며 코드를 만드는 방식 / 원문 해시태그에 등장하나 본문에서 정의되지는 않음.

## 핵심 시사점 / 판단
- **(저자 주장)** 6단계 순서 준수로 Anthropic 기술 직군 약 80%가 매일 Claude Code를 사용하며, 온보딩이 2~3주로 단축되었다.
- **(검증 필요·불확실)** "80% 매일 사용" 수치, 온보딩 단축의 측정 방법·통제군 존재 여부 — 원문에 근거 미제시.
- **(전이 가능)** 이 6단계 패턴은 Claude Code 외 다른 agentic coding 도구(Cursor, Copilot 등)에도 적용 가능한 일반 원칙일 수 있다.
