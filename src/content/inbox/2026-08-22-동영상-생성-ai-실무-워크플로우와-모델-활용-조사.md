## 조사 범위와 신뢰도

2026년 8월 기준으로 동영상 생성 AI를 **실무에서 실제로 어떻게 쓰는가**를 정리한다. 모델 카탈로그 나열이 아니라 워크플로우 유형, 채택 실태, 비용 구조, 실패 지점에 초점을 둔다.

출처는 대부분 벤더 블로그와 비교 리뷰 글이다. 수치는 방향성 참고용이며, 특히 초당 단가와 도입 효과 통계는 출처 간 편차가 크다. 확인이 필요한 항목은 문서 끝에 따로 모았다.

## 용어 정정: 영상 생성 모델은 LLM이 아니다

영상 생성 모델은 **DiT(Diffusion Transformer)** 계열이다. 영상을 시공간 latent 격자로 인코딩하고 패치로 쪼갠 뒤 트랜스포머로 denoise 한다. 다음 토큰을 예측하는 LLM과 학습·추론 구조가 다르다. autoregressive 방식(프레임·청크 순차 생성)은 긴 영상의 시간적 일관성에서 이론적 강점이 있지만 2026년 현재 DiT를 밀어내지 못했다 — 학습 비용 대비 품질과 확장 용이성에서 DiT가 앞선다.

LLM은 파이프라인의 다른 자리에 들어간다.

```text
LLM          기획 · 스크립트 · 샷 분해 · 프롬프트 확장 · 결과 판정
영상 모델     샷 렌더링
TTS/음악      보이스오버 · 사운드
합성·편집     스티치 · 자막 · 컬러 · 마감
```

실무 스택은 언제나 이 넷의 조합이다. "영상 생성 AI 도입"을 모델 하나 고르는 문제로 잡으면 반드시 어긋난다.

## 실무에서 실제로 쓰는 워크플로우

### 지배적인 것은 T2V가 아니라 I2V다

2026년 프로덕션 작업의 대부분은 순수 text-to-video가 아니라 **시작 프레임을 고정하고 목표 상태로 애니메이션하는 image-to-video**다. 이유는 단순하다. 프롬프트만으로는 결과를 재현할 수 없고, 재현할 수 없으면 클라이언트 작업에 쓸 수 없다.

참조 이미지를 쓰면 텍스트 단독 대비 프롬프트 준수도가 최대 40% 올라간다는 측정이 있다. 5초를 넘는 분량이면 image+text 하이브리드를 쓰라는 것이 현재의 실무 권고다.

| 워크플로우 | 통제력 | 실무에서 쓰는 자리 |
|---|---|---|
| T2V (텍스트만) | 낮음 | 컨셉 탐색, 무드 클립, 스톡 대체 |
| **I2V (시작 이미지 고정)** | 중간 | **프로덕션 기본값**. 제품·브랜드 샷 |
| Reference-to-video (참조 N장) | 높음 | 시리즈물 캐릭터·의상·로케이션 일관성 |
| Keyframe / first-last frame | 높음 | 정해진 A에서 B로의 전환, 컷 연결 |
| V2V / restyle | 중간 | 실사 촬영분 스타일 변환 |
| Avatar / lipsync | 매우 높음 (구도 고정) | 사내 교육, 세일즈, 뉴스형 |
| Inpaint / extend / upscale | 부분 | 후처리, 객체 제거, 길이 확장 |

### 파이프라인 규모 4단계

```text
Tier 1  단발 프롬프트          프롬프트 → 클립 → 끝
Tier 2  샷 단위 조립           기획 → 샷 분해 → 샷별 생성 → 선별 → 편집·사운드
Tier 3  에이전트 오케스트레이션  위 과정을 LLM 에이전트가 주도, 사람은 승인 게이트만
Tier 4  완전 자동 파이프라인     소재 소스 → 생성 → 자막·TTS → 멀티 플랫폼 배포
```

**Tier 2가 "영상다운 영상"이 나오는 최소 단위다.** 현장에서 표준화된 6단계는 다음과 같다.

1. 스크립트와 스토리보드를 로드한다
2. 캐릭터 시트와 월드 레퍼런스를 **락**한다
3. 스타일 블록을 붙여 act 단위로 샷을 생성한다
4. 쓸 만한 것만 골라 스티치한다
5. 러프컷을 다시 검수하고 노트를 반영한다
6. 편집 툴에서 마감한다 (사운드·컬러·자막)

2단계의 "락"이 이 워크플로우의 핵심이다. 여기를 건너뛰면 3단계 이후의 모든 재생성이 낭비가 된다.

**Tier 4**는 faceless 숏폼 양산 전용이다. `스프레드시트 소재 → LLM 스크립트 → 이미지·영상 생성 → TTS → Creatomate·Shotstack 합성 → 유튜브·틱톡 업로드`를 n8n 같은 오케스트레이터로 무인화한다. 공개 템플릿이 다수 있어 진입 장벽이 낮지만, 산출물 품질 상한도 낮다.

### 실행 위치 선택

| 방식 | 대표 | 적합 조건 |
|---|---|---|
| SaaS UI | Runway, Kling, LTX Studio | 편집까지 한 곳에서. 소규모 팀, 클라이언트 작업 |
| API 애그리게이터 | fal.ai, Replicate | 모델 라우팅과 A/B가 필요한 자동화 |
| 로컬 / 셀프호스트 | ComfyUI + Wan / LTX-Video | 대량 반복, 커스텀 LoRA, 한계비용 최소화 |

ComfyUI 노드 그래프가 로컬 워크플로우의 사실상 표준이다. `T2V + I2V + 업스케일`을 한 그래프에 묶을 수 있고 기성 워크플로우 파일이 널려 있다.

## 실제로 많이 쓰는 모델

### 생성 품질 프론티어

- **Seedance 2.0 / 2.5** (ByteDance) — 현재 최상위권. 2.5는 30초 네이티브 원패스 생성, 멀티모달 참조 최대 50개, 3D 화이트박스 프리비주얼. 다만 **공식 개발자 API가 아직 없어** 서드파티 경유가 필요하다
- **Veo 3.1** (Google) — 네이티브 오디오 동시 생성. 시네마틱 프롬프트 준수와 카메라 무브가 강점
- **Kling 3.0** (Kuaishou) — 2026-02 출시. **음소 단위 다중 화자 립싱크**가 독보적. 인물 모션 리얼리즘 우수
- **Hailuo 2.3 / MiniMax H3** — 키프레임 제어(시작 프레임 고정, 핀 프레임 간 보간)
- **Luma Ray 3.2**, **Grok Imagine Video 1.5** — 속도·비용 균형

### 워크플로우 강자

**Runway Gen-4.5**는 모델 단품 순위보다 **툴체인 때문에** 채택된다. 에이전시·스튜디오·브랜드 팀이 단일 생성기가 아니라 생성·편집·변환을 아우르는 풀 프로덕션 스택으로 쓴다. 실무에서 원 모델 품질보다 **예측 가능성**이 더 중요하다는 것이 반복해서 나오는 관찰이다.

### 오픈웨이트

- **Wan 2.2 / 2.7** (Alibaba) — 오픈웨이트 중 가장 범용적. MoE diffusion 백본으로 denoising을 전문가 네트워크에 분산해 적은 연산으로 상위 품질
- **LTX-Video / LTX-2.5** (Lightricks) — 속도·효율 최적화, **VRAM 12GB에서도 구동**
- **HunyuanVideo 1.5** (Tencent) — 시네마틱 비주얼, 특히 I2V
- **CogVideoX-1.5**, **Mochi 1**, **SkyReels V1** — 경량·특화

오픈웨이트가 클로즈드 SaaS 품질에 근접했고 한계 추론비용이 사실상 0이라는 점이 2026년의 큰 변화다.

### 아바타 특화

정면 토킹헤드는 별개 카테고리로 봐야 한다. **HeyGen Avatar IV**가 미세 표정·제스처 제어와 속도(1분 영상 3분 이내, 175개 언어 음성 클론)에서, **Synthesia**가 전신 시네마틱 퍼포먼스와 멀티 카메라 앵글에서 우위다. 범용 영상 모델의 립싱크가 따라오고 있지만 이 용도에서는 전용 플랫폼이 여전히 유리하다.

### 이탈: Sora 2

**OpenAI Sora 2는 2026-04-26 deprecated, API는 2026-09-24 종료**로 알려져 있다. 신규 통합 대상이 아니다. 오디오 포함 T2V 상위권이 ByteDance·Alibaba·Kuaishou 중심으로 재편된 것이 현재 지형의 특징이다.

## 비용을 결정하는 것은 초당 단가가 아니다

이번 조사에서 가장 실무적으로 중요한 발견이다.

> 비용을 실제로 결정하는 변수는 모델의 초당 단가가 아니라 **반복률(iteration rate)** — 한 샷을 건지는 데 몇 번 생성하는가다.

관찰된 수치는 다음과 같다.

- 3분짜리 숏 하나에 **원본 300~500초**를 생성하게 된다. 같은 장면을 2~3회 재생성하는 일이 흔해 최종 컷에 쓸 분량을 확보하려면 **개별 클립 80~150개**가 나온다
- 생성 레이어 기준 완성 1분당 **13~220달러**. 편차의 원인은 모델 티어가 아니라 반복률이다
- 초당 0.10달러 기준으로 수익성을 맞추려면 **1차 성공률 80% 이상**이 필요하다

즉 모델 비교표에서 초당 단가 몇 센트를 아끼는 것보다 **재생성을 한 번 줄이는 설계**가 훨씬 크게 작용한다. 조명이 틀리거나 캐릭터 의상이 드리프트해서 계속 다시 돌리는 루프가 2026년 가장 흔한 실패 패턴이다.

## 반복률을 낮추는 실무 기법

병목은 생성이 아니라 **일관성**이다 — 얼굴, 조명, 목소리가 컷 사이에서 유지되지 않는 것. 대응 수단은 셋이다.

1. **참조 이미지 고정** — 캐릭터·의상·로케이션 시트를 먼저 만들고 모든 샷에 붙인다
2. **시드 락과 연속성 토큰** — 한 시퀀스에는 같은 시드 ID를 쓰고, 피사체를 매 프롬프트에서 **동일한 단어**로 기술한다. 결과가 어긋나면 시드를 고정한 채 실패 원인이 되는 단어만 바꾼다
3. **계층적 프롬프트** — 넓은 장면에서 시작해 기술 디테일과 모션 스케일로 좁힌다. 프롬프트에 넣을 항목은 영상 종류, 피사체, 동작, 환경, 샷 프레이밍, 카메라 앵글, 카메라 무브, 조명, 색, 무드, 페이싱, 타이밍, 오디오, 대사, 연속성, 출력 규격

한 줄로 요약하면 **생성을 덜 하고 계획을 더 하는 쪽**이 싸다.

## 기업 도입 실태

수치 신뢰도는 낮지만(대부분 마케팅 통계) 방향은 일관적이다.

- 마케팅 팀의 78%가 분기당 최소 한 캠페인에 AI 생성 영상을 사용
- 포춘 500의 73%가 콘텐츠 워크플로우에 AI 영상 도구를 통합
- 용도 분포에서 **제품 데모·설명 영상이 물량 기준 약 31%**로 최대
- 그 밖에 광고 크리에이티브 대량 생산, 사내 교육, 140개 언어 이상 로컬라이제이션

주목할 점은 **선두 용도가 시네마틱 창작이 아니라 제품 데모와 로컬라이제이션**이라는 것이다. 통제력이 높고 실패 비용이 낮은 워크플로우(아바타, I2V)에 물량이 몰려 있다는 뜻으로 읽힌다.

## 확인이 필요한 항목

1. **Sora 2 API 종료일(2026-09-24)** — 사실이면 마이그레이션 기한이 한 달 남았다는 의미
2. **Seedance 2.x 공식 API 존재 여부** — 서드파티만 있다면 프로덕션 의존은 위험
3. **초당 단가** — 같은 Kling 3.0을 두고 0.029달러와 0.09~0.14달러가 동시에 보고된다. 해상도·길이·오디오 포함 여부·경유 플랫폼에 따라 수 배 차이가 나므로 대상 프리셋으로 직접 벤치하는 것 외에 방법이 없다
4. **도입 효과 통계** — 78%, 73%, 4.2배 ROI 등은 모두 벤더 측 자료다
