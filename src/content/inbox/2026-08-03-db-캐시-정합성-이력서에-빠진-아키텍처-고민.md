## TL;DR
- Redis 조회 최적화만 쓰고 **정합성 파열**을 설계하지 않으면 운영 장애로 이어진다.

## 큰 그림
```
DB 커밋 ──▶ 캐시 무효화 요청(Redis)
                │
        ┌───────┴────────┬────────────┬──────────┐
        ▼                ▼            ▼          ▼
   [TTL 의존]   [Delayed Double   [CDC 구독]  [폴링]
                 Delete]
        │                │            │          │
   단순/구멍     락+재시도      로그 기반    지연 수용
   (저자 주장)   (트랜잭션 밖)   (Debezium)  (단순·확실)
```

## 핵심
- 저자는 백엔드 서류 40건 중 대부분이 **Redis 조회 성능 개선**만 강조하고, 데이터 변경 시점의 캐시 정합성 문제는 다루지 않았다고 **주장**한다.
- 정합성 파열은 DB 커밋과 Redis 삭제 요청이 **서로 다른 트랜잭션 바운더리**에 있기 때문에 발생한다. 한쪽이 실패하면 롤백이 불가능하다.
- 면접에서 이 실패 시나리오를 물으면 답변이 두 축으로 갈린다: **TTL로 버티기** vs **CDC 기반 비동기 갱신**. 저자는 후자를 실무형으로 평가한다.

## 깊이
- **[Delayed Double Delete]** DB 업데이트 전후로 Redis 키를 두 번 삭제하되, 사이에 짧은 지연을 둬 replication lag를 흡수하는 패턴. 저자는 이를 "고민한 흔적"의 예로 언급만 하고 상세 메커니즘은 **원문에 없음**.
- **[CDC + 메시지 큐]** Debezium 등이 DB binlog를 구독해 변경 이벤트를 스트리밍하면, 애플리케이션 실패와 무관하게 캐시 갱신이 보장된다. 단, 실시간성이 전제될 때 가치가 크다(**저자 주장**).
- **[폴링 대안]** 실시간성이 필수 아니면 지연을 감수하고 주기적으로 맞추는 편이 **"훨씬 단순하고 확실"**하다고 저자는 결론 내린다. 어떤 간격·부하인지는 **원문에 없음**.
- **[락 타임아웃 결합]** 분산 락으로 동시 쓰기를 막되 타임아웃으로 교착을 방지하는 설계 축을 언급. 구체적 구현은 **원문에 없음**.

## 용어 풀이
- **정합성 파열** — DB와 캐시의 값이 엇갈리는 상태. 비유: 장부에 적힌 재고와 실제 창고 재고가 다른 상황. 비유 깨짐: 캐시는 복사본이므로 '원본 하나'라는 장부 비유는 분산 환경의 복제본 다수를 놓친다.
- **CDC(Change Data Capture)** — DB 변경 로그를 실시간 구독하는 패턴. 비유: CCTV로 창고 입출고를 녹화. 비유 깨짐: CDC는 이벤트 스트림이지 녹화본이 아니며, 순서 보장이 중요하다.
- **트랜잭션 바운더리** — 원자성이 보장되는 작업 경계. Redis 호출은 보통 이 경계 밖에 있어 롤백이 안 된다.
- **Delayed Double Delete** — 쓰기 전후 두 번 캐시를 지우는 기법. '이중'은 안전망, '지연'은 읽기 경쟁을 피하는 완충.

## 시각 자료
| 접근법 | 실시간성 | 구현 복잡도 | 실패 대응 | 저자 평가 |
|---|---|---|---|---|
| TTL_only | 낮음 | 매우 낮음 | 시간 경과 | 부적합 암시 |
| Delayed Double Delete | 중간 | 중간 | 재시도+락 | 긍정적 언급 |
| CDC(Debezium)+MQ | 높음 | 높음 | 로그 기반 보장 | 실무형 |
| 폴링 | 낮음 | 낮음 | 주기 재동기화 | "단순·확실" |

## 핵심 시사점 / 판단
- **(저자 주장)** 이력서의 "Redis로 성능 개선" 서술은 정합성 설계가 빠지면 불완전하다.
- **(저자 주장)** 실시간성이 핵심이 아니라면 폴링이 가장 현실적인 선택지다.
- **(검증 필요·불확실)** 40건 서류 중 몇 건이 정합성을 기술했는지 수치 근거 없음.
- **(원문에 없음)** 각 패턴의 실제 장애 사례, 지표(지연·비용), 규모별 적합성.
