## TL;DR
- (저자 주장) 집중력은 한 가지 원인이 아니라 **주의 경제 앱 → 직장 채팅 문화 → LLM 과의존**이 층층이 쌓이며 약화되었고, 회복에는 '도망갈 출구를 없애는' 환경 설계가 핵심이다.

## 큰 그림
```
[집중력]
   │
   ▼  약화 요인 (시간 순 누적)
   ├── 1. 주의 경제 플랫폼 (스마트폰·Medium·HN·YouTube)
   │      └─ "지루함 탈출구" 상시 제공
   ├── 2. 직장 채팅 문화 (Slack, 회의)
   │      └─ 실제 작업 vs bullshit 비율 왜곡
   └── 3. LLM 과의존
          └─ 병렬 의뢰 → 정신적 과부하 + 결과 속도 중독
   │
   ▼  회복 시도
   ├── 타이머 + 차단 / 라이브 스트리밍(감시의 눈)
   ├── 대체 습관(독서, 식물 가꾸기)
   └── LLM은 'end-to-end 위임'만
```

## 핵심
- 저자는 과거(대학 시절)에는 LaTeX 직접 작성, 대수 문제 풀이처럼 **'도망갈 출구가 없는' 구조** 덕분에 집중을 유지했다고 회고한다. 이후 스마트폰 앱→블로그 플랫폼→직장 Slack→LLM 순으로 **지루함을 회피할 출구가 하나씩 추가**될 때마다 집중 지속 시간이 단축되었다는 것이 글의 중심 서사다.
- LLM은 이중적 역할을 한다. 연구·작업을 위임할 수 있지만, 위임 중에도 머릿속에서 해당 작업을 붙들게 되어 **병렬 과부하**를 유발하고, 즉각적 결과에 길들여져 논문을 읽는 등 느린 작업을 더 꺼리게 된다고 저자는 주장한다.

## 깊이
- **[주의 경제]** 2015년경엔 폰을 침대에서 분리하는 것으로 충분했지만, 이후 컴퓨터에서도 Medium/HN/YouTube가 **수동적 브라우징 출구**로 자리 잡으며 "의도적 활동"(게임·독서·코딩)이 잠식되었다. *(저자 관찰, 정량 근거 원문에 없음)*
- **[Slack 문화]** 주당 8시간 Slack 사용(과거 본인 실험)을 근거로, "10%만 일해도 괜찮은" 환경이 오프라인 작업(프로그래밍)의 집중 습관까지 망가뜨렸다고 본다. DHH·Spakhm의 'bullshit ratio' 개념을 인용하여 자기 경험을 보강.
- **[LLM 과의존]** "LLM에게 맡기고 다른 일을 해도 머릿속에서 놓지 못한다"는 진술이 핵심. 생산성은 LLM이 **end-to-end로 오류 없이 끝낼 수 있는 작업 위임**에서만 나오며, 상호작용 모드에서는 대기·수정 비용 때문에 오히려 느리다고 평가. *(저자 체감, 벤치마크 아님)*

## 용어 풀이
- **attention economy(주의 경제)** — 사용자 체류 시간을 상품화하는 플랫폼 모델. 비유: "무료인 척하는 식당이 사실은 당신의 시선을 메뉴로 파는 곳." 깨지는 점: 모든 플랫폼이 그렇진 않으며(예: 정적 블로그), 오프라인 주의 산만도 설명 못 함.
- **bullshit ratio** — Spakhm이 쓴 개념으로, 실제 가치 창출 작업 대비 형식적 작업(회의·채팅) 비율. 비유: "식사의 영양소 대비 장식 비율." 깨지는 점: 측정 기준이 주관적.
- **vibe coding** — LLM에 문맥을 던져 결과물을 받아 쓰는 느슨한 코딩. 비유: "요리 대신 배달." 깨지는 점: 유틸리티 수준에선 유효할 수 있어 '나쁘기만 한' 습관은 아님.

## 핵심 시사점 / 판단
- (저자 주장) 집중력 회복은 의지력이 아니라 **환경 설계**(타이머, 차단, 감시의 눈, 대체 습관) 문제다.
- (저자 주장) LLM의 최적 사용은 '상호작용'이 아니라 **오류 없이 end-to-end 위임 가능한 영역**으로 제한하는 것이다.
- (검증 필요·불확실) Slack이 실제 코딩 집중력을 영구 저하시킨다는 인과 관계는 개인 관찰에 기반하며, 통제 연구는 원문에 없음.
- (검증 필요·불확실) LLM 사용이 장기적으로 '느린 작업 회피' 성향을 강화한다는 주장은 체감 수준이며 정량화되지 않음.
