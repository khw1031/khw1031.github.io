## TL;DR
- 알리바바가 사내 2년 사용 후 오픈소스화한 코드 리뷰 도구로, **파일 선택을 deterministic 코드가, 판단만 LLM이 담당**하는 구조가 핵심 차별점이다(저자 주장).

## 큰 그림
```
┌─────────────────────────────────────────────────┐
│              Open Code Review 파이프라인          │
│                                                   │
│  git diff ──► [파일 선정기(코드)] ──► [LLM 판단]  │
│                  │                      │         │
│            deterministic           line-by-line   │
│            rule-based              review 의견    │

  ┌────────┬────────┬────────┬──────┐

  └────────┴────────┴────────┴──────┘
```

## 핵심
- 기존 LLM 코드 리뷰는 **어떤 파일을 볼지도 모델이 결정**하므로, 변경분이 크면 파일을 빠뜨리거나 불필요한 파일까지 읽어 토큰이 폭증하는 문제가 있다.
- Open Code Review는 이 문제를 **파일 선정 단계를 코드가 담당**하는 방식으로 분리한다. deterministic 로직이 관련 파일을 먼저 추리고, LLM은 추려진 파일 안에서만 판단하므로 컨텍스트 윈도우 낭비가 줄어든다.
- 이 구조적 차이로 인해 **동일 모델을 사용해도** 정확도와 토큰 효율에서 우위를 갖는다고 저자는 주장한다.

## 깊이
- **[벤치마크 수치]** 저자 주장에 따르면 공식 벤치마크에서 F1 25.1%를 기록, 동일 모델 기반 Claude Code 리뷰의 11.6% 대비 약 2배 높다. 토큰 사용량은 38.5만 vs 566만으로 **약 15배 차이**. 다만 이 수치가 어떤 벤치마크 세트·어떤 모델에서의 결과인지는 **원문에 없음(불확실)**.
- **[파일 선정 전략]** "코드가 먼저 고른다"는 표현은 rule-based 또는 graph-based 정적 분석을 의미하는 것으로 보이나, 구체적인 선정 알고리즘(diff parsing, dependency graph 등)은 원문에 기술되지 않았다.
- **[통합 범위]** Claude Code·Codex·Cursor 플러그인 + CI 연동을 지원하며, Apache 2.0 라이선스로 상업적 사용에도 제약이 없다. GitHub 스타 1.4만은 커뮤니티 초기 관심을 시사하나, 장기 유지보수 여부는 **검증 필요**.

## 용어 풀이
- **F1 score** — 정밀도(precision)와 재현율(recall)의 조화평균 / 비유: "맞은 것"과 "빠뜨리지 않은 것"의 균형 점수 / 깨지는 지점: 코드 리뷰처럼 "오탐 비용"과 "미탐 비용"이 비대칭인 상황에선 F1만으로 품질 판단이 불충분.
- **Deterministic 파일 선정** — 모델 추론 없이 규칙·구문 분석으로 파일을 고르는 것 / 비유: 사서가 목차만 보고 관련 챕터를 먼저 뽑아주는 것 / 깨지는 지점: 규칙이 커버하지 못하는 cross-cutting 변경(설정 파일, 문서 등)은 누락 가능.

## 시각 자료
| 항목 | Open Code Review | Claude Code 리뷰 |
|---|---|---|
| 파일 선정 방식 | 코드(deterministic) | LLM 판단 |
| F1 (저자 주장) | 25.1% | 11.6% |
| 토큰 사용량 | 38.5만 | 566만 |
| 라이선스 | Apache 2.0 | — |

> ⚠️ 위 수치는 2차 출처(인스타그래ม 게시물) 기반이며, 벤치마크 조건·모델 종류 등 실험 설계 세부사항은 원문에 없음.

## 핵심 시사점 / 판단
- **(저자 주장)** 파일 선정을 코드로 분리한 아키텍처가 토큰 효율과 정확도를 동시에 개선했다.
- **(저자 주장)** 알리바바가 2년간 사내 검증 후 오픈소스화하여 실전 안정성이 있다.
- **(검증 필요·불확실)** F1 25.1% 자체가 절대적으로 높은 수치는 아님 — 코드 리뷰 도구의 실용적 품질은 오탐률(false positive rate)과 개발자 수용도에 크게 좌우되므로, 벤치마크 수치만으로 실제 효용을 판단하기 어려움.
- **(검증 필요·불확실)** "알리바바가 2년간 썼다"는 주장은 마케팅 문구일 수 있으며, 현재 내부 사용 여부는 별도 확인 필요.
