## TL;DR

- herdr은 터미널 멀티플렉서인데, 차별점은 멀티플렉싱이 아니라 **패널 안에서 도는 코딩 에이전트를 인식하고 그 상태를 위로 올려준다**는 것이다. 상태 어휘는 `idle` / `working` / `blocked` / `done` / `unknown`이고, pane → tab → workspace로 롤업된다.
- 제어 표면이 **3계층으로 같은 API를 공유**한다 — 에이전트 스킬(SKILL.md) → `herdr` CLI → 로컬 소켓 API. CLI는 소켓 API의 래퍼이고, 문서는 "대부분의 자동화는 CLI에서 시작하고, 원시 소켓은 직접 요청/응답 제어나 장기 이벤트 구독이 필요할 때만"이라고 못 박는다.
- CLI는 명령 수가 많지만 축은 셋이다 — **레이아웃**(workspace/tab/worktree/pane 토폴로지), **pane**(원시 터미널), **agent**(인식된 에이전트). "pane은 에이전트가 없어도 존재하고, agent는 그 pane을 현재 점유한 인식된 프로세스"라는 문장이 이 구분의 정의다.
- 스킬 쪽이 더 배울 게 많다. 명령 목록을 스킬에 박아 암기시키는 대신 **설치된 바이너리를 문법의 권위로 선언**하고 발견 절차만 지시한다. 여기에 `HERDR_ENV=1` 환경 게이트, description에 박아 넣은 발동 억제 문구, 실패 모드 문서화가 붙는다.

## 1. 구조: 무엇 위에 무엇이 있나

배경 서버가 실제 터미널 프로세스를 소유하고, 클라이언트가 붙어서 렌더링한다. 개념은 아래 포함 관계 하나로 정리된다.

```
session (배경 서버 네임스페이스)
└── workspace  w1        프로젝트 단위 컨테이너
    └── tab    w1:t1     workspace 안의 레이아웃
        └── pane w1:p1   실제 터미널 (right/down으로 분할)
            └── agent    pane을 점유한 인식된 코딩 에이전트
```

공개 ID는 불투명하지만 안정적인 핸들이고, 닫힌 tab/pane ID는 재사용되지 않는다. pane을 다른 workspace로 옮기면 **새 workspace 한정 pane ID를 받는다** — 그래서 `pane move` 이후에는 응답의 `.result.move_result.pane.pane_id`나 살아 있는 에이전트 이름으로 이어가야 한다.

구현은 Rust, 라이선스 Apache-2.0. 소켓 기본 경로는 `~/.config/herdr/herdr.sock`이고, 이름 있는 세션은 `~/.config/herdr/sessions/<name>/herdr.sock`로 갈린다. 해석 우선순위는 `--session` → `HERDR_SOCKET_PATH` → `HERDR_SESSION` → 기본 세션 순.

### 자동화는 사실상 8개 명령

명령표가 길어도 스크립트가 실제로 쓰는 건 이 여덟이다. 왼쪽 넷은 에이전트 해석 없는 원시 터미널, 오른쪽 넷은 수명 주기를 해석하는 에이전트 표면이다.

| 원시 터미널(pane) | 에이전트(agent) |
| --- | --- |
| `pane run` — 명령 텍스트 + Enter를 원자적으로 전송 | `agent start <name> --kind <kind> --pane <id>` |
| `pane send-text` — Enter 없이 텍스트만 | `agent prompt <target> <text> [--wait]` |
| `pane send-keys` — 논리 키/코드 조합 | `agent send-keys <target> esc\|ctrl+c` |
| `pane wait-output --match\|--regex` | `agent wait --until <status>` |

### 출력 읽기 소스 4종

`pane read` / `agent read`의 `--source`가 갈리는 지점인데, 잘못 고르면 로그가 깨져 보인다.

| 소스 | 무엇 |
| --- | --- |
| `visible` | 현재 렌더된 뷰포트 |
| `recent` | 최근 출력, soft wrap 포함 |
| `recent-unwrapped` | soft wrap을 이어 붙인 최근 출력 — 로그·트랜스크립트 기본값 |
| `detection` | 에이전트 탐지에 쓰는 평문 하단 버퍼 스냅샷. **`agent read` 전용**이고 `pane read`에는 없다 |

### 규약과 환경 변수

- 대부분의 제어 명령은 **JSON을 반환한다.** 성공 응답은 요청 `id` + `result`(`type` + 페이로드), 실패는 `code` + `message`.
- **서버 오류는 stderr에 JSON + exit 1, CLI 문법 오류는 exit 2.** 스크립트에서 두 실패를 구분할 수 있다.
- herdr이 관리 pane에 주입하는 컨텍스트: `HERDR_ENV=1`, `HERDR_PANE_ID`, `HERDR_TAB_ID`, `HERDR_WORKSPACE_ID`, `HERDR_BIN_PATH`. 그 밖에 `HERDR_CONFIG_PATH`, `HERDR_SESSION`, `HERDR_SOCKET_PATH`, `HERDR_PROCESS_DETECTION`(native/child-groups), `HERDR_LOG`, `HERDR_DISABLE_SOUND`.

## 3. 탐지와 상태 어휘

탐지는 pane의 포그라운드 프로세스를 식별한 뒤 두 경로 중 하나를 탄다. **통합(훅)이 설치돼 있으면** 에이전트가 직접 상태를 보고하고(권위 있음), 아니면 **TOML 화면 매니페스트**를 하단 버퍼 스냅샷에 매칭해 분류한다. 매니페스트는 원격에서 갱신받을 수 있다(`server update-agent-manifests`).

상태 어휘에서 헷갈리는 두 지점을 SKILL.md가 직접 정의해 놓았다.

- `idle`은 "입력 대기 + **그 탭이 포커스된 UI에서 보였음**"이고, `done`은 같은 idle 상태인데 **보이지 않은 채로 배경 작업이 끝난** 경우다. 즉 done/idle을 가르는 건 작업 내용이 아니라 사람이 봤느냐다. 탭을 포커스하거나 focus 계열 명령을 쏘면 seen 처리되지만, **CLI read는 seen 처리하지 않는다.**
- `unknown`은 에이전트는 있는데 자신 있게 분류하지 못한 상태이고, 문서는 "**완료를 증명하지 않는다**"라고 명시한다.

`agent explain <target> --json`이 이 분류의 근거를 뜯어보는 진단 명령이고, `--file <path> --agent <label>`로 저장된 픽스처에 대고 돌릴 수도 있다.

### 세션 참조는 에이전트마다 형태가 다르다 (실측)

통합 훅은 상태만이 아니라 **네이티브 대화 세션 참조**도 보고한다(`pane report-agent-session --agent-session-id|--agent-session-path`). `herdr agent get <target>`의 `.result.agent.agent_session`에서 읽히고, `kind`가 두 값을 갖는다.

| 에이전트 | `agent_session.kind` | 값 | 확인 방법 |
| --- | --- | --- | --- |
| claude | `id` | 세션 UUID | 훅이 `hook_input.session_id` 보고 |
| codex | `id` | 스레드 UUID (rollout 파일명과 동일) | 훅이 `session_id`/`CODEX_THREAD_ID` 보고 |
| pi | `path` | 세션 `.jsonl` 절대 경로 | 확장이 path 우선, 없으면 id |

주의할 점 두 가지를 직접 확인했다. **codex는 첫 턴을 돌기 전까지 `agent_session`이 `null`**이다(pi는 기동 즉시 path가 잡힌다). 그리고 codex 훅이 신뢰 검토 대기 상태면 세션 참조 보고가 막히는데, herdr은 그 모달을 `blocked`가 아니라 `idle`로 분류했다.

## 4. 에이전트 스킬(SKILL.md) 내용

설치는 `npx skills add herdrdev/herdr --skill herdr -g`(전역) 또는 `-g` 없이 프로젝트 로컬. 스킬 시스템이 없는 에이전트는 파일 내용을 지시문에 붙여 넣으면 된다. 분량은 200줄이 안 된다.

### 4.1 발동 억제가 frontmatter에 있다

description이 "herdr을 쓰라고 명시적으로 말할 때만 쓰라"에서 끝나지 않고 한 문장을 더 붙인다 — "**단지 배경 터미널·위임·병렬 작업이 도움이 될 것 같다는 이유로 쓰지 말 것.**" 스킬 설명에 negative trigger를 박아 오탐 발동을 막는 패턴이다.

### 4.2 첫 규칙은 환경 게이트

```bash
test "${HERDR_ENV:-}" = 1
```

실패하면 "herdr 안에서 실행 중이 아니다"라고 말하고 **멈춘다.** 밖에서 포커스된 herdr 세션을 들여다보거나 조작하지 않는다. 소켓이 로컬에 열려 있으니 기술적으로는 밖에서도 붙을 수 있는데, 그걸 스킬 층위에서 금지하는 구조다.

### 4.3 명령 목록 대신 발견 절차

스킬은 전체 명령을 나열하지 않는다. "**설치된 바이너리가 명령 문법의 권위다**"라고 선언하고 `herdr --help`부터 시작해 `herdr agent`, `herdr pane`처럼 **서브커맨드 없이 그룹만 실행**해 도움말을 뽑으라고 지시한다. 여기에 두 개의 금지가 붙는다.

- **맨 `herdr`은 발견용으로 실행 금지** — TUI를 실행/부착해 버린다.
- **변경성 중첩 명령을 인자 없이 찔러보지 말 것** — `herdr workspace create`는 기본값으로 유효해서 그냥 실행된다.

스킬이 CLI 버전과 함께 낡는 문제를 문서화 대신 위임으로 푼 셈이다.

### 4.4 ID는 예측하지 말고 응답에서 읽는다

- `workspace create` → `.result.workspace`, `.result.tab`, `.result.root_pane`
- `tab create` → `.result.tab`, `.result.root_pane`
- `pane split` → `.result.pane`
- 대상 지정은 `--current` 우선. 타깃을 생략하면 **UI가 포커스한 pane**이 잡히는데, 그건 사용자나 다른 클라이언트의 것일 수 있다.
- 에이전트 이름은 `[a-z][a-z0-9_-]{0,31}`, 살아 있는 에이전트 사이에서 유일해야 하고, 이름은 현재 pane 점유자를 따라다니다 종료·해제·교체되면 지워진다. agent 명령은 터미널 ID나 맨 종류 라벨(`claude` 같은)은 받지 않는다.

### 4.5 기본 토폴로지 정책

사용자가 명시하지 않으면 **현재 탭의 형제 pane + 현재 작업 디렉터리**가 기본이다. workspace/tab/worktree를 새로 만들거나 다른 cwd를 쓰지 않는다.

```bash
herdr pane layout --pane "$HERDR_PANE_ID"          # 먼저 모양을 본다
herdr pane split --current --direction right --cwd "$PWD" --no-focus
```

넓은 pane은 오른쪽, 좁거나 긴 pane은 아래로 쪼갠다. 같은 방향 반복 분할로 못 쓸 만큼 좁은 열을 만들지 말라는 지침까지 들어 있다. 사용자 포커스는 계속 호출한 pane에 둔다(`--no-focus`).

### 4.6 에이전트 시작·조율

`agent start`는 **레이아웃을 만들지 않는다** — 이미 존재하는, 대화형 프롬프트에 셸이 포그라운드로 떠 있는 빈 pane을 요구한다. 감지 성공까지 기다렸다가 반환하며 기본 시작 타임아웃은 30초. 네이티브 인자는 `--` 뒤에만 넘긴다.

```bash
herdr agent start reviewer --kind codex --pane <pane-id> -- <agent-args...>
herdr agent prompt reviewer "Review the current diff." --wait --timeout 120000
```

`agent prompt`는 텍스트와 인코딩된 Enter를 **원자적으로** 보내며 pane의 bracketed-paste 모드를 존중한다. `--wait`는 처음 안정된 `idle`/`done`/`blocked`에서 풀리므로 그 기본값을 `--until`로 다시 쓰지 말라고 한다. `--until`은 "이미 돌고 있는 에이전트가 입력을 요청할 때까지" 같은 상태 특정 워크플로에만 쓴다.

실패 모드도 명세돼 있다. **비작업 상태에서 보낸 프롬프트가 5초 안에 수명 주기 변화를 만들지 못하면 `agent_prompt_stalled`를 반환**하고 무한 대기하지 않는다. 반대로 이 대기는 개별 턴이 아니라 상태를 추적하므로, 이미 작업 중이었다면 **진행 중이던 턴의 완료가 대기를 만족시켜 버릴 수 있다.**

### 4.7 alternate screen 폴백

`--lines`를 키워도 완료된 응답이 더 안 나오면, 그 pane은 에이전트를 **터미널 대체 화면(alternate screen)**에서 돌리는 중일 가능성이 높다. 대체 화면을 벗어난 행은 herdr의 호스트 스크롤백에 들어가지 않아 줄 수를 늘려도 복구되지 않는다. 이때만 폴백으로 "응답 전문을 임시 디렉터리에 마크다운으로 쓰고 경로만 답하라"고 시킨 뒤 파일을 직접 읽는다. **처음 프롬프트에서 파일 출력을 요구하지는 말라**는 단서가 붙어 있다.

### 4.8 안전·조율 규칙

- 배경 작업은 `--no-focus`.
- 대상은 `--current`·명시 pane ID·유일한 에이전트 이름으로. 다른 클라이언트의 포커스에 기대지 않는다.
- ID는 JSON 응답에서 파싱한다. 사이드바 순서나 예시에서 유도하지 않는다.
- **자기가 만들지 않은** workspace/tab/pane/session은 닫지 않는다.
- 활성 세션에서 `herdr server stop`을 실행하지 않는다(pane 프로세스까지 죽는다). 메인 herdr 프로세스를 죽이지 않는다. 격리가 필요한 실험은 이름 있는 테스트 세션으로.

## 5. 눈에 띈 설계 포인트

문서 자체보다, 스킬을 이렇게 썼다는 사실이 이 저장소의 스킬 작성 규약에 참고가 된다.

- **명령 목록을 스킬에 복사하지 않는다.** 대신 "바이너리가 권위" + 안전한 발견 절차 + "변경성 명령은 찔러보지 말 것"이라는 금지. 도구 버전이 스킬보다 빨리 움직일 때 쓸 수 있는 패턴이다.
- **description에 negative trigger.** "이럴 때 쓰라"만이 아니라 "이런 이유로는 쓰지 말라"를 같은 자리에 둔다.
- **환경 변수 게이트로 권한 경계를 만든다.** 소켓은 열려 있어도 스킬 층위에서 "밖에서 조작 금지"를 선언한다.
- **실패 모드를 어휘로 만들어 문서화한다.** `agent_prompt_stalled`, alternate screen 스크롤백 소실, `unknown`이 완료를 뜻하지 않음 — 셋 다 "이럴 땐 이렇게"까지 붙어 있다.
- **관찰이 상태를 바꾼다는 것을 명시한다.** CLI read는 seen 처리하지 않고 focus만 한다 — `done`과 `idle`의 구분이 여기 걸려 있어서, 이걸 모르면 상태 판정을 오독한다.

## 열린 질문

- 훅 기반 통합 없이 화면 매니페스트만으로 도는 에이전트의 상태 판정이 실제로 얼마나 견디는가. 문서는 "탐지 품질이 다르다"까지만 말한다.
- `agent prompt --wait`가 "이미 작업 중이면 진행 중이던 턴 완료로 만족될 수 있다"는 조항은, 여러 프롬프트를 연달아 던지는 스크립트에서 경합이 될 것 같다. 실제 회피 패턴이 문서에 없다.
- 플러그인 시스템(manifest action + event hook)과 에이전트 스킬의 역할 경계 — 어디까지를 스킬로, 어디부터를 플러그인으로 두는지는 이번에 확인하지 않았다.
- 이 저장소 관점의 실용 질문: `herdr`을 쓰면 지금의 서브에이전트 병렬화와 무엇이 달라지는가. herdr은 **프로세스 수준 병렬**(진짜 터미널에서 도는 별개 CLI 세션)이고, 서브에이전트는 **컨텍스트 수준 병렬**이라 겹치지 않는다. 실제로 필요해지는 지점은 "다른 모델/다른 CLI를 동시에 돌리고 상태를 한 화면에서 본다"일 때다.
