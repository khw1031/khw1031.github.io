## TL;DR
- i-have-adhd는 기능을 추가하지 않고 코딩 에이전트의 **말하는 방식만** 10개 규칙으로 제어하는 오픈소스 스킬이다.

## 큰 그림
```
i-have-adhd (스킬 = 규칙 묶음)
│
├── 입력: 에이전트 출력 스타일
│   └── 기능 변경 ✗ / 출력 형식만 변경 ○
│
├── 규칙 10개
│   ├── 구조 ── 결론 우선 → 다음 행동 제시 → 번호 매기기
│   ├── 제약 ── 목록 ≤5개 / 시간=분 단위 / 서두·맺음·요약 금지
│   └── 태도 ── 곁가지 억제 / 모호어("조금") 금지
│
├── 적용 방식
│   └── 파일 1개 생성 → Claude Code·Codex 세션에 상시 활성
│
└── 품질 안전장치
    └── 응답 평가 하네스 (정확성·안전성 기준선 미달 시 배포 차단)
```

## 핵심
- 이 프로젝트의 출발점은 단순하다: AI가 답을 설명 속에 파묻는 문제를 해결하겠다는 것이다.(저자 주장) 기능을 더하는 대신 **출력 형식만 규제**하는 규칙 10개를 묶어 스킬로 배포했다.
- 규칙은 세 층으로 나뉜다. 먼저 **구조**(결론→다음 행동→번호)가 응답의 뼈대를 잡고, **제약**(목록 상한, 시간 단위, 서두 금지)이 군더더기를 자르며, **태도** 규칙이 모호한 표현과 곁가지로 새는 것을 막는다.
- 적용은 파일 하나로 끝난다. Claude Code와 Codex에 플러그인처럼 붙어 모든 세션에서 항상 켜지므로, 사용자가 매번 프롬프트를 반복할 필요가 없다.

## 깊이
- **[구조 규칙]** "결론을 먼저, 다음 행동을 마지막에"라는 원칙은 ADHD 사용자의 정보 처리 패턴을 반영한 것으로 보인다.(저자 주장) 일반적인 chain-of-thought 프롬프팅이 사고 과정을 먼저 보여주는 것과 **정반대 방향**이다.
- **[품질 하네스]** 저장소 내에 응답 품질 평가 하네스가 포함되어 있으며, 정확성과 안전성이 기준선보다 떨어지면 배포하지 않는 규정이 있다.(저자 주장) 단순 스타일 규칙을 넘어 **회귀 테스트** 개념을 도입한 것으로 해석된다. 다만 구체적인 평가 지표와 기준선 수치는 원문에 없다.
- **[성장 속도]** 공개 두 달 만에 GitHub 스타 1만 4천을 넘겼다고 한다.(저자 주장 · 불확실) 이것이 출력 스타일 제어에 대한 수요를 증명하는지, 아니면 초기 화제성 효과인지는 추가 확인이 필요하다.

## 용어 풀이
- **스킬(skill)** — 에이전트에 행동을 지시하는 규칙 파일 묶음 / 비유: 직원에게 주는 "업무 매뉴얼" / 비유가 깨지는 점: 매뉴얼은 사람이 판단하여 적용하지만, 스킬은 에이전트가 매 세션 자동 로드한다.
- **하네스(harness)** — 출력을 자동으로 평가하는 테스트 틀 / 비유: 시험 채점 기계 / 비유가 깨지는 점: 채점 기계는 정답이 고정돼 있지만, 이 하네스는 LLM 응답의 정확성·안전성을 평가하므로 기준이 유동적일 수 있다.
- **프러그인(plugin)** — 기존 시스템에 기능을 덧붙이는 모듈 / 여기서는 파일 하나로 세션에 상시 적용되는 방식을 의미.

## 시각 자료

| 구분 | 내용 | 효과 |
|------|------|------|
| 구조 | 결론 우선 → 다음 행동 → 번호 | 인지 부하 감소 |
| 제약 | 목록 ≤5, 시간=분, 서두 금지 | 응답 길이 통제 |
| 태도 | 모호어·곁가지 금지 | 정보 밀도 상승 |
| 안전 | 평가 하네스 내장 | 품질 기준선 유지 |

## 핵심 시사점 / 판단
- (저자 주장) 출력 스타일만 바꿔도 에이전트 사용 경험이 크게 개선될 수 있으며, 기능 추가 없는 규칙 파일 하나로 충분하다.
- (저자 주장) ADHD 사용자를 염두에 두고 설계했으나, 정보 과부하를 겪는 모든 사용자에게 적용 가능한 보편적 원칙으로 읽힌다.
- (검증 필요) 스타 1만 4천이라는 수치가 실제 사용량·만족도와 직결되는지 불확실.
- (불확실) Claude Code 외 다른 에이전트(Cursor, Windsurf 등)에서의 호환성은 원문에 없음.
