### Adapter 패턴의 소비자 중심 경계

**핵심:** Adapter의 본질은 메서드 이름을 바꾸는 것이 아니라, 소비자가 외부 시스템의 표현과 규약을 모르도록 경계에서 차이를 흡수하는 것이다. 내부의 안정적인 계약과 외부의 변하기 쉬운 표현 사이에서 요청·응답·상태·오류·호출 규약을 번역한다.

#### 배경

`pay()`를 `requestPayment()`로 바꾸는 결제 예시는 Adapter의 최소 형태는 보여 주지만, 이름 변경만으로는 별도 경계가 필요한 이유를 충분히 설명하지 못한다. 실제 가치는 외부 시스템의 지식이 여러 소비자에게 퍼지는 것을 막는 데 있다.

#### 세부 내용

- 소비자가 의존하는 `PaymentPort`는 애플리케이션 목적의 계약이고, `PaymentAdapter`는 그 계약을 외부 결제사 규격으로 번역하는 인프라 경계다.
- Adapter는 필드명뿐 아니라 자료형, 통화·날짜 형식, 외부 상태 코드, 오류 체계, 인증과 호출 순서를 변환할 수 있다.
- Adapter가 흡수할 것은 같은 의미의 다른 표현이다. 외부 시스템이 내부에 필요한 의미를 더 이상 제공하지 않는다면 의미를 꾸며 내지 말고 내부 계약과 요구사항을 다시 판단해야 한다.
- `checkout`처럼 도메인 규칙을 호출하고 결제·저장을 조율하는 코드는 보통 애플리케이션 로직이다. “내 코드 대 외부 코드”와 “도메인 로직 대 인프라 로직”은 같은 구분이 아니다.
- BFF는 클라이언트 전용 스키마로 변환할 때 아키텍처 수준의 Adapter 역할을 수행할 수 있다. 다만 BFF는 서비스 경계와 배포 단위이고, Adapter는 계약을 변환하는 역할이므로 둘은 동의어가 아니다.

### Domain의 사업적 판단 책임을 드러내는 표현

**핵심:** Domain을 “사업의 참과 거짓을 판단하는 곳”이라고 표현하기보다, **사업 규칙에 따라 가능한 행동과 올바른 상태 변화를 결정하는 곳**이라고 표현한다. 단순히 “판단 지점”이라고만 하면 Application의 실행 분기와 Adapter의 변환 판단까지 Domain으로 오해할 수 있다.

#### 세부 내용

- Domain은 취소된 주문의 결제 가능 여부처럼 사업 정책에 근거한 판단을 소유한다.
- Application은 주문 조회, 규칙 검사, 결제 요청, 저장처럼 유스케이스의 실행 순서를 조율한다.
- Adapter는 외부 상태 코드와 내부 결과처럼 서로 다른 표현을 번역한다.
- 짧게 구분하면 “Domain은 무엇을 해도 되는지와 그 결과 어떤 상태가 되어야 하는지를 결정하고, Application은 그것을 언제 어떤 순서로 실행할지 결정한다.”

### Client–Server 아키텍처의 통신 계약과 신뢰 경계

**핵심:** Client–Server 아키텍처의 본질은 화면과 서버를 나누는 것이 아니라, 서로 독립된 두 실행 주체가 명시적인 통신 계약을 통해 협력하게 만드는 것이다. Client는 사용자의 목적을 요청으로 표현하고 결과를 소비하며, Server는 신뢰할 수 있는 규칙과 상태를 바탕으로 요청을 처리한다.

#### 역할과 관계

- Client는 사용자 입력, 화면 표시, 화면 전용 상태, 요청 전송과 응답 소비를 담당한다.
- Server는 인증과 권한, 입력 검증, 애플리케이션 흐름, 도메인 규칙, 데이터 저장과 응답 생성을 담당한다.
- 둘은 서로의 내부 코드를 알지 않고 요청·응답 형식, 인증, 오류 코드와 상태 의미를 포함하는 API Contract에 의존한다.
- Client와 Server는 기술 종류가 아니라 요청 관계에서의 역할이다. BFF는 Browser에는 Server지만 다른 Backend를 호출할 때는 Client다.

#### 신뢰 경계

Client는 버튼 노출이나 입력 안내처럼 가능한 행동을 사용자에게 안내할 수 있지만, 중요한 행동을 최종 승인하는 사업 규칙은 일반적으로 Server가 검증한다. Client는 사용자가 우회하거나 변조할 수 있으므로, Client에서 취소 버튼을 숨겼다는 사실만으로 주문 취소 규칙이 지켜지지는 않는다.

#### Adapter와의 관계

Client–Server는 시스템을 독립된 실행 주체로 나누는 아키텍처 구조이고, Adapter는 그 경계에서 표현 차이를 흡수하는 설계 역할이다. Client의 화면 모델과 Server의 API 응답이 다르면 Adapter가 필드명, 상태 코드와 표시 형식을 변환한다.

#### 분리의 비용

네트워크 경계에서는 일반 함수 호출과 달리 지연, timeout, 연결 실패, 중복 요청, 계약 버전 불일치와 부분 실패가 발생한다. 따라서 오류 규격, 재시도 정책, 인증과 권한, idempotency, 상태 재조회와 요청 추적을 함께 설계해야 한다. Client–Server로 분리한다는 것은 코드를 다른 폴더에 두는 것이 아니라, 통신 실패와 독립적인 변경을 감당하는 경계를 만드는 것이다.
